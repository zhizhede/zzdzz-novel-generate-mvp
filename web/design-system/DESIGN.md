# 小说生成平台设计系统（novelgen）

> Category: Writing & Publishing
> 羊皮纸底、墨蓝单一彩色、中文衬线承担层级；为**数据密集的写作运维台**调过密度，为**中文长文阅读**补过排版参数。

本文件是 OpenDesign 意义上的 `DESIGN.md` —— 给 agent 的规范散文（canonical design prose）。任何为本平台生成界面的 agent 应先读本文件，再读 `tokens.css`，必要时读 `element-plus.css`。

---

## 1. 视觉主题与气质

一句话：**暖羊皮纸作底，墨蓝作唯一彩色动作，暖中性灰承担层级，中文衬线承担性格。**

它不是一套通用后台皮肤。这个产品同时干两件气质相反的事——**读小说**和**盯生成队列**——所以设计系统必须在同一个调性里同时服务两种密度：

- **阅读面**要像纸（暖底、衬线、松行高、段首缩进），让人愿意读三十万字；
- **运维面**要像仪表（密、对齐、稳定、数字不抖），让人能一眼扫过 23 个页签。

统一这两者的粘合剂是「**暖中性**」：所有灰都带黄褐底调（R ≈ G > B），**没有任何冷灰蓝**。冷灰蓝是"屏幕感"的来源，也是这个系统最想避免的东西。

**关键特征**：

- 羊皮纸画布 `#f5f4ed` —— 任何页面背景都不用纯白
- 单一彩色：墨蓝 `#1b365d`，占比 ≤ 5% 版面
- 四段暖灰前景梯（`--fg` / `--fg-2` / `--muted` / `--meta`），**全部通过 WCAG AA**
- 中文衬线（TsangerJinKai02 / 思源宋体）承担标题，无衬线承担界面文字
- 环状阴影（`0 0 0 1px`）与低语阴影，禁硬投影
- 状态标签用**实色三元组**（文字/底/边成对算过对比度），不用半透明底
- 数据面**不受宽度上限约束**（见 §5）

## 2. 颜色

### 来源与改造

基座是 OpenDesign 的 `kami`（紙 / 纸）——该目录里唯一从设计之初就为 zh-CN 排版做的系统，且其印刷节奏与数据表密度天然接近。相对基座做了三处品牌化改造，其中**第二处是硬需求**：

### 改造 A：表面与前景沿用，但把对比度当验收项

沿用 kami 的暖中性梯，但逐条实算过对比度。这同时修掉现状的一处系统性缺陷——当前代码里的次要文字色**全部不过 AA**：

| 用途 | 现状 | 实测 | 本系统 | 实测 |
|---|---|---|---|---|
| 主文字 | — | — | `--fg` `#141413` | **16.7:1** |
| 次级/表头 | `#606266` | 5.5:1 ✓ | `--fg-2` `#3d3d3a` | **9.9:1** |
| 说明文字 | `#999`（134 处） | **2.58:1 ✗** | `--muted` `#504e49` | **7.5:1** |
| 元信息/时间 | `#bbb`（20 处） | **1.74:1 ✗** | `--meta` `#6b6a64` | **4.9:1** |
| 品牌彩色 | `#409eff`（8 处） | **2.52:1 ✗** | `--accent` `#1b365d` | **11.0:1** |
| 警告色 | `#e6a23c`（35 处） | **1.98:1 ✗** | `--warn` `#7a4606` | **7.0:1** |

> 判定基准：WCAG 2.1 AA 正文 4.5:1。这是**可测量的缺陷修复**，不只是审美替换。

### 改造 B：重设状态色（硬需求）

kami 自述「面向印刷，几乎不需要状态色」——它的三个语义色（`#4a6b3a` / `#8a6b1f` / `#8a3a30`）为印刷调暗，实测在 0.14 alpha 底上：warn 只有 **3.82:1**（不过 AA），且四族 tint 挤成一片暖灰、两两几乎不可分辨。

本平台恰恰相反：**状态标签是主要信息载体**（排队中 / 生成中 / 已完成 / 已停止 / 待审批 / 正文已成 …）。故重设五族：

| 族 | 语义 | 文字 | 底 | 边 | 文字在底上 |
|---|---|---|---|---|---|
| success | 已完成 / 通过 | `#2c6639` | `#d9e0d4` | `#b9c9b7` | 5.07:1 |
| attn | 生成中 / 待办 | `#7a4606` | `#e4dccd` | `#d0c0a8` | 5.70:1 |
| danger | 停止 / 失败 | `#8a3a30` | `#e6dad3` | `#d5bcb4` | 5.62:1 |
| accent | 进行中 / 信息 | `#1b365d` | `#d6d9d9` | `#b4bbc2` | 8.54:1 |
| neutral | 排队 / 取消 | `#5f5e58` | `#e0dfd8` | `#c8c7c0` | 4.87:1 |

生成方式可复现：`底 = mix(色, #f5f4ed, 0.14)`、`边 = mix(色, #f5f4ed, 0.30)`。

> **纪律**：状态**不得只用颜色表达**。五族的底在 0.14 alpha 下相近（通道差 7–21），底色只作装饰，**语义由标签文字承担**。任何新状态标签都必须带文字。

### 强调色

墨蓝 `#1b365d`（11.0:1）是唯一彩色。深度已足，故 hover **不混黑**（会看不见），改用「色值不变 + 抬升」；active 用手挑的 `#142a48`。

## 3. 排版

### 中文优先

与基座 kami 相反：本系统 `:root` **直接落中文栈**，英语才是覆盖。

```
--font-display: "TsangerJinKai02", "Source Han Serif SC", …, serif   ← 标题、书名、章题
--font-body:    "PingFang SC", "Microsoft YaHei", …, sans-serif      ← 界面文字
```

衬线承担"文学性"（书名、章题、阅读面），无衬线承担"工具性"（表格、表单、按钮）。这个分工不要混：**界面控件一律无衬线**，衬线只出现在内容侧。

### 字号阶（面向运维台密度）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--text-xs` | 12px | 表格元信息、标签文字（元信息下限，不再往下） |
| `--text-sm` | 13px | 密集 UI 默认（对应现状 12/13px 共 213 处） |
| `--text-base` | 14px | 标准正文 |
| `--text-md` | 15px | 强调正文 |
| `--text-lg` | 17px | 卡片标题 |
| `--text-xl` | 20px | 页面标题 |
| `--text-2xl` | 24px | 对话框标题 |

行高：界面 `--leading-body: 1.6`，表格行 `--leading-dense: 1.45`。

### 阅读面（C-extension）

中文长文需要比印刷文档更大的行高，且**必须有段首缩进**（这是中文排版惯例，也是现状完全缺失的一项）：

| 令牌 | 值 | 说明 |
|---|---|---|
| `--reading-fs-1..4` | 16 / 17 / 18 / 20px | 用户可选四级 |
| `--reading-leading` | 1.9 | 比界面松得多 |
| `--reading-indent` | `2em` | 段首缩进两字符 |
| `--reading-measure` | `46em` | 版心 ≈ 46 全角字/行 |

`--reading-measure` 用 `em` 而非 `px` 是刻意的：1em ≈ 1 个全角字，用户调大字号时版心**同步变宽，每行字数不变**。这是"按比例"而不是"设上限"。

## 4. 间距、圆角、阴影、动效

- **间距**：4px 栅格（`--space-1..12`）。卡片内边距 16–24px，区块间距 24px。
- **圆角**：印刷式克制——标签 2–4px，按钮/输入 4px，卡片/容器 8px，特性容器 12px。**控件用小半径是刻意的**：运维台控件小且密（遍地 `size="small"`），大圆角会显得松垮。
- **阴影**：三级——`--elev-flat` / `--elev-ring`（1px 环，主用）/ `--elev-raised`（低语，`0 4px 24px rgba(0,0,0,.05)`）。**禁硬投影**。
- **动效**：`--motion-fast 150ms` / `--motion-base 200ms` / `--ease-standard cubic-bezier(.2,0,0,1)`。hover 是低语抬升，不做位移与亮度抖动。

## 5. 布局与宽度口径（产品硬规则）

**数据面不受宽度上限约束。**

- 表格一律 `width: 100%` 占满内容区，**不设任何 px 上限**。
- 多余宽度按比例分给弹性列（`min-width`），定宽列只在真正定宽处使用（章号/状态/操作）。窗口变宽时是**内容列变宽**，不是表格变宽。
- **禁止「声明列宽合计 > 容器宽度」**：这是一类真实缺陷的根因——规划页卷纲表声明列宽合计 1120px 却压了 `max-width: 980px`，导致列被压扁、`时间跨度` 表头竖排成 4 行、末列被裁，同时右侧 43% 窗口全空。
- 确需上限时用比例或字号相对单位表达（`min(100%, Nvw)` / `rem` / `em` / `ch`），**不用 px**；真要用 px 硬上限须登记理由（如登录卡的 360px 居中卡）。
- 因此 `--container-max` 在本系统里声明为 `100%`（= 不设上限），而非基座的 `1120px`。长文限宽走 `--reading-measure`。

## 6. 组件约定

- **状态标签**：五族实色三元组，语义靠文字不靠颜色（§2）。
- **表格**：满宽（§5）；表头 `white-space: nowrap` 并给列宽下限；数字列用 `font-variant-numeric: tabular-nums`，避免多行数字抖动。
- **按钮**：主按钮墨蓝实心（`--accent` 底 + `--accent-on` 文字）；次按钮用环 + 暖沙底。一屏内主按钮不超过一个。
- **信息层级**：优先用 `--fg-2` / `--muted` / `--meta` 表达强弱，而不是缩小字号——**字号不再往下压到 12px 以下**。

## 7. Do / Don't

**Do**

- 用令牌，不写裸值。任何硬编码的 `#999` 这类都是回归。
- 需要"更弱"的文字时降层级（`--muted` → `--meta`），不要缩字号。
- 长文一律走 `--reading-*`，包括缩进。
- 新增状态标签时先在五族里挑，挑不到再加族并补算对比度。

**Don't**

- 不要用纯白 `#ffffff` 作页面底，也不要用冷灰蓝。
- 不要给数据表设 px 上限，不要写「列宽合计 > 容器宽度」的组合。
- 不要用颜色单独表达状态。
- 不要引入第二彩色（含 hover 亮度抖动）。
- 不要在正文里用衬线以外的字体做强调——用层级和留白。
