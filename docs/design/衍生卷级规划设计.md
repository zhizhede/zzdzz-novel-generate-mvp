# 随机衍生系统：卷级规划设计

> 状态：设计方案，未落码。  
> 适用：`derive_gen` 独立库、`derive-app` 独立流程，不依赖主站 `novel_gen` 的卷规划实现。

## 1. 目标

把当前 ⑥a 的“单卷章节规划”升级为：

```text
创作框架
  → 全书规模（短篇 / 中篇 / 长篇）
  → 卷数与卷边界
  → 每卷事件与卷末闭合
  → 每卷章数与拍组
  → 逐章正文
```

卷是故事结构的一等对象，不再是章节规划之后的展示字段。

### 必须解决

- 45 章不再被当成一个连续事件审；可自然拆成 3–5 卷，每卷独立收束。
- “可以拆分为多卷”只是框架允许，不能自动扩成长篇。
- 短篇框架即使字数带允许更多，也必须允许 AI 选短篇。
- 每卷都有本卷事件、本卷闭合、卷末钩子；最后一卷才有全书总真相和角色终局。
- 规划失败时能定位到“卷级问题”，不再用末章/单拍补丁解决。

## 2. 设计边界

### 不改

- `derive_gen` 独立部署、独立认证、独立库。
- 现有 ⑤采样、素材池、⑧质检的基本职责。
- 现有 `run / beat_instance / chapters` 的正文与断点续跑语义。

### 新增

- 卷级规划表。
- `chapters.volume_no`。
- `beat_instance.volume_no`（可选，但推荐显式落库）。
- ⑥a 的卷规划单元与卷级校验。
- ⑥b 的卷上下文注入。
- ⑧ 的卷级闭合检查。

## 3. 数据模型

### 3.1 `derive_volume_plan`

每个 run 的每一卷一行。

```sql
CREATE TABLE derive_volume_plan (
    id              BIGINT PRIMARY KEY,
    run_id          BIGINT NOT NULL REFERENCES run(id),
    novel_id        BIGINT NOT NULL REFERENCES novels(id),
    volume_no       INT NOT NULL,
    from_chapter    INT NOT NULL,
    to_chapter      INT NOT NULL,
    arc             VARCHAR(128) NOT NULL,
    local_event     TEXT NOT NULL,
    local_closure   TEXT NOT NULL,
    next_hook       TEXT NOT NULL DEFAULT '',
    global_role     VARCHAR(16) NOT NULL DEFAULT 'LOCAL',
    status          VARCHAR(16) NOT NULL DEFAULT 'PLANNED',
    created_time    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_time    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX uq_derive_volume_plan_no
    ON derive_volume_plan(run_id, volume_no);
```

字段口径：

- `local_event`：本卷独立事件/案件的一句核心描述。
- `local_closure`：本卷结束时必须兑现的局部落点。
- `next_hook`：下一卷的钩子；最后一卷为空。
- `global_role`：`LOCAL` 普通卷，`FINAL` 最终卷。

### 3.2 `chapters`

新增：

```sql
ALTER TABLE chapters ADD COLUMN volume_no INT;
```

约束：

- 每章必须属于一个卷（迁移后回填）；
- `volume_no` 不得跳号；
- 同一 run 的章节范围连续、不重叠。

### 3.3 `beat_instance`

新增：

```sql
ALTER TABLE beat_instance ADD COLUMN volume_no INT;
```

章节已经能推出卷，但显式落库便于：

- 卷级拍数统计；
- 卷级重排；
- 卷级质检；
- 不依赖章节表反查。

## 4. 规划输出契约

### 4.1 规模与卷数

⑥a-0 输入必须包含：

- 完整 `param_intent`（用户创作框架）；
- 字数区间（仅边界，不是目标）；
- 产品形态、结局、节奏；
- 拍清单规模；
- 用户是否给了明确目标章数/每卷章数（如有）。

输出：

```json
{
  "storyScale": "SHORT | MEDIUM | LONG",
  "volumeCount": 1,
  "chapterCount": 12,
  "chapterAvg": 2200,
  "reason": "框架是单案调查，按短篇单卷"
}
```

规则：

1. 先读创作框架，判断短篇/中篇/长篇；
2. 框架说短篇，就允许 1 卷、少章；
3. “可以拆分为多卷”是可选能力，不是必须扩卷；
4. 字数区间只做边界，不能为了凑字数自动扩卷；
5. 卷数由独立事件弧决定，不由字数机械决定。

### 4.2 卷级规划

⑥a-1 输出：

```json
{
  "volumes": [
    {
      "volume_no": 1,
      "from_chapter": 1,
      "to_chapter": 11,
      "arc": "罪人塔失踪案",
      "local_event": "密室失踪与第一次追凶",
      "local_closure": "本卷失踪案手法揭晓，主犯留下下一层线索",
      "next_hook": "灰潮会渗透痕迹指向下一卷",
      "global_role": "LOCAL"
    },
    {
      "volume_no": 4,
      "from_chapter": 34,
      "to_chapter": 45,
      "arc": "攻岛真相",
      "local_event": "总攻与组织核心揭露",
      "local_closure": "组织核心落网，主角完成身份与继承抉择",
      "next_hook": "",
      "global_role": "FINAL"
    }
  ]
}
```

硬校验：

- 章号从 1 连续覆盖到 `chapterCount`；
- 每卷至少 1 章；
- `volume_no` 连续；
- 普通卷 `next_hook` 不可为空；
- 最终卷 `global_role=FINAL` 且 `next_hook` 为空；
- 每卷必须有一个“本卷闭合”的拍/情绪/事件落点；
- 全部拍必须分配且只能分配一次。

### 4.3 章级规划

⑥a-2 在**单卷范围**内生成章节，不再让模型面对整本 45 章。

输入只带：

- 当前卷的 `local_event / local_closure / next_hook`；
- 当前卷拍清单；
- 当前卷前后衔接；
- 当前卷章数目标。

章内拍数允许按场景节奏浮动；系统只校验：

- 本卷拍全部用完；
- 本卷章号连续；
- 每章至少 1 拍；
- 本卷末章包含本卷闭合落点。

## 5. 流程改造

### ⑤采样

仍然产出拍清单和素材，但增加：

- 记录框架规模判断所需的原始 `param_intent`；
- 不把默认字数带当成故事规模。

### ⑥a-0 规模

由 AI 根据框架判断：

- 短篇 / 中篇 / 长篇；
- 全书章数；
- 卷数；
- 章均字数。

### ⑥a-1 卷规划

AI 先分卷，系统校验后再进入章规划。卷规划失败只重试卷规划，不回滚已完成素材。

### ⑥a-2 逐卷章规划

每卷独立生成章与拍组。窗口上限按“卷内章数”控制，不再出现整本最后一窗承压。

### ⑥b 具体稿

每章生成时注入：

- 当前卷的局部事件；
- 当前卷闭合要求；
- 下一卷钩子；
- 最后一卷才注入全书真相与人物终局要求。

### ⑦正文

按章写正文，卷边界不改变⑦的单章断点。

### ⑧质检

分两层：

- 卷级质检：本卷事件是否闭合、本卷钩子是否成立；
- 全书质检：总真相、人物终局、全书闭环。

## 6. 提示词设计

新增三类独立提示词，避免一个规划提示词承担所有层级：

| 用途 | 输入 | 输出 |
|---|---|---|
| `derive_scale` | 创作框架、字数边界、拍数、形态 | 规模、章数、卷数、章均 |
| `derive_volume_plan` | 框架、拍清单、全书章数 | 每卷事件/闭合/钩子 |
| `derive_chapter_plan` | 单卷上下文、卷内拍清单 | 卷内章节与拍组 |

关键口径写死在提示词里：

- 框架优先于字数带；
- 可多卷不等于必须多卷；
- 每卷必须有本卷闭合；
- 最后一卷才有全书终局；
- 不再按固定每章拍数反推章数；
- 不再要求每窗精确拍数。

## 7. API 与前端

新增只读/重排端点：

```text
GET  /api/derive/runs/{id}/volumes
POST /api/derive/runs/{id}/volumes/replan
POST /api/derive/runs/{id}/volumes/{volumeNo}/replan
```

前端 run 详情增加“卷结构”卡：

- 卷号、章号范围、卷事件；
- 本卷闭合；
- 下一卷钩子；
- 本卷状态；
- 最终卷标记。

“清空⑥+数据”同时删除 `derive_volume_plan`、章节、拍实例、具体稿，保留⑤配置。

## 8. 迁移策略

1. 新增 V120：卷表、`chapters.volume_no`、`beat_instance.volume_no`。
2. 历史 run：
   - 单卷视为 `volume_no=1`；
   - 已有章节按顺序回填 `volume_no=1`；
   - 不自动重排历史内容。
3. 新 run 才启用卷级规划。
4. 增加开关 `derive.volume-planning.enabled`，默认启用；旧逻辑保留只用于回滚。

## 9. 验收用例

### 短篇

- 框架：单案、短篇；
- 期望：1 卷、少章，不因字数带自动扩卷。

### 45 章轻小说

- 框架：多卷允许；
- 期望：3–5 卷，每卷 8–13 章，每卷有本卷闭合和下一卷钩子；
- P6 不再把卷三/卷四的新事件判成“单卷支线过载”。

### 长篇闭合

- 最后一卷有总真相、角色终局；
- 普通卷的 `next_hook` 均存在；
- 全书拍数无丢失、无重复。

## 10. 不做

- 不把主站 `VolumePlanService` 直接复制进 derive；两套系统独立。
- 不在本次设计中继续加“每窗精确拍数”规则。
- 不用合成末拍替代真正的卷级结构。
