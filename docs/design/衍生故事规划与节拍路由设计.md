# 衍生故事规划与节拍路由设计

> 状态：第一阶段已落码并部署宝塔；V121/V122 已应用，真实 V2→⑥b→P6 链路已实弹。
>
> 适用范围：`derive_gen` 独立库与随机衍生 ⑥a/⑥b/⑦/⑧ 链路。

## 1. 背景与问题

当前随机衍生已经具备：

- ⑤无指向素材抽样与主线焊接；
- ⑥a 规模判断、卷骨架、章与拍实例落库；
- ⑥b 全书人物、persona、brief、真相卡与逐窗章纲；
- P6 立项闸；
- ⑦逐章正文与世界状态账；
- ⑧全书质检。

但当前 ⑥a 在规模判断后，主要按“剩余拍数 ÷ 剩余章数”的顺序配额切拍。它能保证结构和数量完整，却不能保证：

- 无指向拍被分配给最合适的小事件；
- 每卷高光角色拿到与其弧光相关的拍；
- 角色功能在需要时被使用，并在合理阶段发生冲突；
- 前卷线索在后卷按计划回声、误读和兑现；
- 每卷局部闭合与大主线推进同时成立；
- 角色死亡、离场、知识和关系变化在写正文前就形成完整因果链。

因此需要增加“故事合同、角色合同、线程账、章功能槽、全局拍路由、状态模拟”六类规划能力。

## 2. 设计目标

### 2.1 必须做到

1. 用户的显式卷数、每卷章数、角色高光卷和终局要求是硬约束。
2. 每卷具有独立问题、局部答案、局部闭合和大主线增量。
3. 每卷非末卷具有下一卷钩子，最终卷关闭既定线程。
4. 角色不只是 persona，还必须有叙事功能、高光、冲突和兑现。
5. 无指向拍先匹配功能槽位，再具体化；不再按顺序平均切章。
6. 素材不足时允许生成 `SYNTHETIC` 无指向拍，素材无关时允许路由阶段跳过。
7. 写正文前模拟角色生死、位置、知识、关系和线索状态。
8. P6 与⑧能区分“⑥a结构错误”和“⑥b文字错误”，避免错误回炉。

### 2.2 明确不做

- 不新建“角色状态表”；实时状态继续以 `world_states` 为准。
- 不分别新建线索表、关系表、物件表；统一使用 `derive_story_thread`。
- 不新建章槽位表；章功能合同存入 `chapters.plan_contract`。
- 不新建第二套拍表；扩展现有 `beat_instance`。
- 不引入图数据库、微服务或新队列系统。
- 不在本阶段改变⑦逐章断点续跑主流程。

## 3. 核心概念

| 概念 | 含义 |
|---|---|
| 故事脊柱 | 全书背景大事件、最终真相、最终选择、真相阶梯 |
| 卷合同 | 每卷局部问题、错解、真解、大主线增量、闭合与钩子 |
| 角色计划 | 角色的叙事功能、不可替代贡献、高光、冲突、弧光前后状态 |
| 故事线程 | 跨章或跨卷追踪的线索、关系和物件生命周期 |
| 章功能槽 | 某章必须完成的结构功能，不先绑定具体素材 |
| 拍路由 | 把无指向拍分配给卷、章和功能槽，或明确跳过 |
| 状态事实 | 某章结束后角色在哪里、是否活着、知道什么、关系如何 |
| 计划变更 | 写作前计划产生的死亡、离场、得知、关系改变等不可逆变化 |

## 4. 总体架构

设计分为五个部分：

```text
1. 故事与卷合同
2. 角色功能与故事线程
3. 章功能槽与拍路由
4. 状态、知识与因果校验
5. ⑥b/P6/⑦/⑧接入
```

目标流程：

```text
⑤ 采样
→ ⑥a-0 SCALE
→ ⑥a-1 SPINE
→ ⑥a-2 VOLUMES
→ ⑥a-3 CHARACTERS
→ ⑥a-4 SLOT_ROUTE_V1..Vn
→ ⑥a-5 VALIDATE
→ ⑥b 具体稿
→ P6 立项闸
→ ⑦ 正文
→ ⑧ 全书质检
```

### 4.1 职责分层

```text
故事层：故事脊柱 + 卷合同
人物层：角色功能 + 角色弧 + 关系线程
结构层：章功能槽 + 拍路由
事实层：plan-time 状态模拟 + runtime world_states
执行层：⑥b具体化 + ⑦正文 + ⑧质检
```

## 6. AI 输出合同

所有 AI JSON 先由 `LlmJson` 解析与结构校验，再落库。结构错误带回具体错误重试，最多 3 轮。

### 6.1 SCALE

```json
{
  "storyScale": "SHORT|MEDIUM|LONG",
  "volumeCount": 4,
  "chapterCount": 48,
  "chapterAvg": 2800,
  "reason": "用户显式给出四卷人物高光结构",
  "scopeDecision": "SINGLE_VOLUME|MULTI_VOLUME|NEED_CONFIRMATION",
  "scopeEvidence": ["第二卷给角色A高光", "第三卷给角色B高光"]
}
```

规模优先级固定为：

```text
显式卷号/卷数
> 用户独立卷级目标
> 产品形态
> 字数边界
> 拍数
```

用户显式写“四卷”时，`volumeCount` 必须为 4。
用户只写一卷且未表达后续卷目标时，默认 1 卷。
既有“可以多卷”但没有实际卷级事件时，仍按 1 卷。
只有语义确实冲突且无法安全默认时，返回 `NEED_CONFIRMATION`。

### 6.2 SPINE

```json
{
  "mainMystery": "贯穿全书的背景大事件",
  "finalTruth": "最终真相",
  "finalChoice": "主角最终必须作出的选择",
  "truthLadder": [
    {
      "volumeNo": 1,
      "reveals": ["背景事件真实存在"],
      "forbidden": ["主谋身份"],
      "evidenceThreads": ["GM-CLUE-01"]
    }
  ],
  "globalThreads": []
}
```

真相阶梯必须逐卷增加不可逆信息，不能只换一种说法重复同一事实。

### 6.3 VOLUMES

按 `derive_volume_plan.contract` 输出每卷合同。
每卷必须包含局部问题、错解、真解、大主线增量、高光角色、关系变化、局部闭合和下一卷钩子。

### 6.4 CHARACTERS

按 `derive_character_plan.contract` 输出稳定角色槽。
角色名可以暂未定，先用 `C1..Cn`；⑥b 定名后绑定正式姓名。

### 6.5 SLOT_ROUTE

每次只处理一卷。输出该卷 12 章的章功能槽、拍路由、补拍和跳过原因。

```json
{
  "volumeNo": 2,
  "chapters": [
    {
      "chapterNo": 13,
      "chapterFunction": "VOLUME_HOOK",
      "assignments": [
        {
          "tempSeq": 31,
          "storyLayer": "LOCAL_CASE",
          "beatRole": "HOOK",
          "focusCharacters": ["C1"],
          "appearanceMode": "LIVE"
        }
      ]
    }
  ],
  "syntheticSlots": [],
  "skipped": []
}
```

SLOT_ROUTE 不得新增或删除卷级线程；缺线程时返回结构错误，由 VOLUMES 重做。

## 8. 工作流

### 8.1 ⑥a 单元制

`POST /api/derive/runs/{id}/plan` 仍为幂等推进一个单元。

| unit | 输出 |
|---|---|
| `SCALE` | 规模、卷数、章数、章均 |
| `SPINE` | 大主线、终局、真相阶梯、全局线程 |
| `VOLUMES` | 每卷合同与卷内线程 |
| `CHARACTERS` | 角色槽、功能、弧光、关系和冲突 |
| `SLOT_ROUTE` | 指定卷的 12 章功能槽与拍路由 |
| `VALIDATE` | 全书校验结果 |
| `DONE` | ⑥a 完成 |
| `NEED_SCOPE` | 需要用户确认单卷/多卷和扩卷授权 |

计划状态存入：

```text
run.step_status.steps.PLAN_V2
```

旧 `steps.PLAN` 保留用于历史 run，不迁移、不重算。

### 8.2 ⑥b

⑥b仍按当前 HEAD/BATCH 单元制，但输入改为：

- 当前卷合同；
- 当前角色计划；
- 当前章 `plan_contract`；
- 当前章固定拍路由；
- 当前线程状态；
- 当前角色状态与知识状态。

⑥b不得修改：

- 卷边界；
- 章号；
- 角色高光卷；
- 拍归属章；
- 线程兑现章；
- 死者和知识边界。

### 8.3 P6

P6仍位于⑥b完成后、⑦开写前。

2026-10-21 实弹修订后，P6 不再让模型直接输出 `GO/REWORK/REJECT`。模型只做结构化审稿，
Java 负责终态与回炉目标：

```json
{
  "criteria": {
    "single_rule": {
      "pass": false,
      "severity": "HARD",
      "note": "两套解释规则同时成立",
      "issues": ["第3章暗示超自然控心，第11章又用纯物理机关解释"],
      "repairTarget": "SPINE"
    },
    "budget": {},
    "motive_chain": {},
    "closure": {},
    "function_lock": {},
    "motif_dedup": {}
  },
  "issues": ["汇总结论"],
  "directive": "可执行减法指令"
}
```

裁决矩阵：

| 结构化结果 | Java 动作 |
|---|---|
| 六项全通过，或未通过项仅有 `ADVISORY` | `PASS / GO` |
| 存在 `FIXABLE` 或 `HARD`，第 1~2 轮 | `REWORK`，按最上游目标回炉 |
| 存在 `FIXABLE` 或 `HARD`，第 3 轮 | `FAILED / REJECT` |

`HARD` 不等于第一轮熔断。它只表示根因更深，仍先走两轮定向回炉；真正熔断条件是轮次耗尽。
模型即使额外输出旧 `verdict` 也一律忽略。

回炉目标优先级固定为：

```text
SCALE > SPINE > PLAN_VOLUME:n > DRAFT
```

错误按范围分流：

```text
章纲文字、filled 不合理 → 重做⑥b
章功能、拍路由、卷闭合错误 → 重做对应卷 SLOT_ROUTE
角色弧、线程、主谜或全局真相错误 → 保留规模，从 SPINE 重建 VOLUMES/CHARACTERS/路由/章纲
规模或卷数错误 → 从 SCALE 重判，再走完整故事规划
```

`REWORK` 的轮次、指令和结构化判据保留在 `run.step_status.steps.GATE`。根因回炉会清掉该层的下游产物，
但不会丢失轮次，避免自动流程无限循环。

### 8.4 ⑦与⑧

⑦主流程不变，仍逐章断点续跑。

⑧增加：

- 每卷局部问题、真解和闭合；
- 每卷大主线增量；
- 角色高光的选择、代价与变化；
- 功能冲突是否有前置铺垫；
- 线程是否全部按计划回声和兑现；
- 最终卷是否仍引用未兑现线索；
- 是否出现未解释复活、位置跳跃或超前知识。

本轮不新增逐卷正文队列。卷级 QC 可作为第二阶段优化，本设计第一阶段仍保留全书统一⑧。

## 9. 4卷 × 12章规划模板

### 9.1 四卷结构

| 卷 | 本卷事件 | 大主线增量 | 角色重点 |
|---|---|---|---|
| 第一卷 | 一个局部案件把主角拉入调查 | 证明背景事件真实存在 | 建立角色功能与第一次方法分歧 |
| 第二卷 | 新案件与第一卷出现相同手法 | 发现重复作案规则 | 角色A高光，功能成功但造成关系代价 |
| 第三卷 | 旧案重启，前两卷解释被推翻 | 主角或核心角色与旧事件建立私人联系 | 角色B高光，价值观与关系最深冲突 |
| 第四卷 | 主谋制造最后假结局 | 全部线索汇合，完整真相兑现 | 角色C与主角完成最终选择，全部线程闭合 |

### 9.2 12章功能槽

| 章 | 主功能 | 建议主层 | 2～4拍构成 |
|---|---|---|---|
| 1 | 卷钩子 | LOCAL_CASE | 新事件、主角卷入 |
| 2 | 案件边界 | LOCAL_CASE | 受害者、规则、嫌疑人 |
| 3 | 第一线索 | LOCAL_CASE/MAIN | 本地线索、大主线异常 |
| 4 | 功能首次使用 | CHARACTER_ARC | 角色功能成为调查必要条件 |
| 5 | 冲突种子 | RELATIONSHIP | 支线升温、方法冲突 |
| 6 | 中点反转 | LOCAL_CASE | 案件方向改变 |
| 7 | 假答案 | LOCAL_CASE | 错解、错误安全感 |
| 8 | 功能失效 | CHARACTER_ARC | 代价、关系破裂 |
| 9 | 大主线推进 | MAIN_MYSTERY | 旧线索重新解释 |
| 10 | 高光选择 | CHARACTER_ARC | 主动选择、执行、代价 |
| 11 | 局部真相 | LOCAL_CASE | 责任兑现、真解 |
| 12 | 闭合与钩子 | 多线程 | 局部闭合、大主线新层级、下一卷问题 |

第四卷第11章改为完整真相与责任人兑现，第12章改为角色、关系、线索和世界状态全部收束。

## 10. 硬校验与软校验

### 10.1 硬校验

以下任一失败即拒绝落库或进入重试：

- 显式卷数与用户架构不符；
- 用户指定每卷12章但章节范围不是12章；
- 同拍重复分配；
- 拍既未分配也未给出跳过原因；
- 每章拍数小于1或大于4；
- 非末卷无下一卷钩子；
- 最终卷仍有必须关闭的 OPEN 线程；
- `LIVE` 出场与已死亡/被囚/离场状态冲突；
- 角色使用尚未获得的知识；
- 线程在 `forbiddenBeforeChapter` 之前被解决；
- 最终卷首次出现决定主谋身份、动机或作案链的新证据；
- SLOT_ROUTE 新增未在卷合同中登记的结构线程。

### 10.2 软校验

软校验形成 warning，交给 P6/⑧或模型修订：

- 角色连续超过2章无功能贡献；
- 同类功能连续3拍重复；
- 连续3章只有事件/反转；
- 关系修复前缺少桥接拍；
- 某卷主线增量过弱；
- 高光只有胜利，没有选择或代价。

## 12. 错误处理与幂等

- 每个 AI 单元输出通过结构校验后才落库。
- 每个单元以 `run.step_status.steps.PLAN_V2` 记录完成状态。
- 同一单元重复调用必须复用已落库结果。
- 单卷重规划前先检查该卷正文是否为空；成稿卷默认拒绝重规划。
- 单卷重规划只删除该卷的 `chapters.plan_contract`、拍路由和未成稿章行，不改前后卷已确认合同。
- 重规划导致后续卷线程冲突时，标记后续卷 `NEEDS_REVALIDATION`，不静默覆盖。
- LLM 结构失败最多3轮；耗尽保留上一完成单元，返回可读错误。
- `world_state` 抽取仍 fail-open，但计划阶段的状态模拟是 fail-hard。
