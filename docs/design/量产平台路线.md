# 量产平台路线（高质量 · 多用户 · 多品类）

> 定位：从"单用户 MVP 生成管线"到"多用户按各自思路同时量产不同类别/节奏/文笔/题材/篇幅小说"的演进总图。
> 制定：2026-09-22，依据当日实测数据与用户定调（愿景 + 原创语料资产支撑）。本文是后续数轮开发的锚，进度回写各阶段。

## 一、愿景公式

**多用户 × 各自思路 × {类别, 题材, 文笔, 节奏, 篇幅} × 高质量 × 同时量产（目标基线：100 万字/天）**

拆开是三层工程：①一个用户能无人值守高质量量产（闭环）；②风格可从原创语料批量复制（多样性）；③多人互不干扰地各跑各的（平台）。

## 二、现状账本（2026-09-22 实测）

- **速度（实测与推算，分开说）**：ch65 实测单章串行 12.5 分钟（8 次调用 × 均延迟 94s）。「单道 24h 满负荷 ≈ 39 万字/天、3 道并行超 100 万字/天」是**基于单章实测的算术上限**——持续负载下的限速、自愈重写放大、人工介入停顿均未验证，真值以阶段二压测为准。分道机制已有（`max_parallel_novels`，现值 2）。
- **成本**：ch65 实耗 ≈ 0.4 元/章（闲时价：入 1 / 出 4 元/M tokens）；自愈重写使每章在 14-20 万 tokens 浮动，折 **0.4-0.6 元/章**。百万字/天量级约 120-180 元/天（闲时；高峰 ×2）。成本不是墙。
- **已有地基**：分道队列 + 断点续跑 + 硬中断、卷纲 auto-plan 任务化、三级配置覆盖（书级 gate_config > 平台 tuning > 代码默认）、风格包按书可移植、审校三闸（机械指纹/读者评审/AI 审校）+ 失败自愈梯子、四层记忆（素材卡/事实账/世界状态/伏笔账）、RAG 语义检索、提示词注册表（fail-open）、LLM 台账按章归账。
- **结构性缺口**：`novels.user_id` 字段在但**所有接口零归属校验**；提示词注册表平台级无书级覆盖；全库仅漱石猫一套指纹基线；调度分书道不分用户；共享单一 API key 无限速预算。

## 三、四堵墙——"一个用户无人值守量产"的闭环（阶段二要拆）

1. **人工介入点未闭环（最大）**：伏笔 30 条 PROPOSED 堆积等人采纳；审校硬伤连 auto 模式也转人工；replan 纠偏靠人。300 章/天 × 5% 异常率 = 每天 15 章等人。
   → 对策：伏笔采纳规则化（digest 提议 + 规则引擎自动推进，人工只处理规则打回的）；审校硬伤自动处置策略（重试梯子终态自动化）；失败任务自动重试/放弃策略 + 看板。
2. **记忆园艺不可扩展**：事实账滚动 3 条、伏笔台账推进、canon 裁决现为低频人肉。
   → 对策：账本健康度指标（悬置伏笔年龄/事实冲突计数）+ 自动园艺任务 + 事实账注入窗口参数化（`findRecent` 已参数化、挂 tuning 键即可调，现为滚动 3 条，已核实）。
3. **质量验收无自动化**（已由语料红利解决一半，见 §四-7）。
4. **限速与故障面未压测**：2400 调用/天 × 3 道并发的 MiniMax 限速行为未知。
   → 对策：三书并跑压测轮，采集 429/超时分布，定重试与降级参数。

## 四、特征提取管线——"语料 → 风格包"（阶段三，本路线核心增量）

前提资产：**高质量原创小说语料**（量级待定：本数/字数/品类数——管线批处理与分位口径按此定）。系统侧全部槽位现成，缺的只是编排：

| # | 提取特征 | 系统槽位 | 方法 |
|---|---|---|---|
| 1 | 风格指纹基线（22 项指标带宽） | `style_packs.gate_config` 指纹段 | `GateService.computeMetrics`（静态纯函数）批量跑语料 → 分位聚合 baseline/tolerance/abs_max |
| 2 | 章长预算带 | 卷纲行 budgetMin/Max、`scene_len_*_ratio` | 语料章长/场景长分布 |
| 3 | 评审标准 | `reader_fat_ratio_*` 等五参 | 分两类：机械指标零成本批量提取；**fat_ratio 是读者评审的 LLM 判定值**（已核实 ReviewService 提示词），语料基线须抽样跑 LLM 评审（花 tokens、有判定噪声，不做全量） |
| 4 | AI 腔黑名单 | gate_config.banned_phrases | 对照挖掘：生成稿高频 ∩ 语料零出现，人工过目 |
| 5 | 风格规则 + 范例库 | rulesMd、场景 few-shot 范例 | LLM 辅助定性提取；语料切段入范例库（对白攻坚已验证范例注入有效） |
| 6 | 素材卡/世界观种子 | material_cards + RAG | 语料角色/物品/地点批量提卡 |
| 7 | **golden set** | 抽检验收基准 | 语料即"高质量"的操作定义：生成分布 vs 原著分布的统计对比 |

**形态**：任务化批量作业（类 auto-plan 模式：选语料 → 跑出全套预设 → 人工过目 → 一键落书级配置）。任务枚举可扩（`TaskKind` 现 CHAPTERS/PLAN 两值，加 EXTRACT 即加值+队列分派分支，已核实）。产出即"题材预设库"，多用户开新书即选即用。历史线：重启 `09/0913-新书孵化` 的提取/孵化意图（ImportRunner 导稿能力已有）。

## 五、多租户与运营（阶段四）

- **Enforcement**：novels.user_id 已有**且存量已填**（已核实：现存两书均 user_id=1），补全量接口归属校验（service 层统一守卫）即可；素材/台账经 novel 归属自然隔离。
- **计费配额**：llm_call_log 已按章归账 → 顺链 novel.user_id 滚用户账；配额与超限处置。
- **公平调度**：队列从书道扩用户权重/优先级；API key 限速预算按户分配（必要时 per-user key）。
- **管理面**：用户管理、用量看板、任务总览。

## 七、开放参数与风险

- **语料量级**（待用户提供）：决定批处理规模、分位口径（小语料用稳健分位）、范例库抽样策略。
- **品类代表性**：基线质量上限 = 语料质量；糊弄的语料会产出"过门禁但不好看"。
- **黑名单对照挖掘的假阳性**：语料未覆盖 ≠ 不该用，需人工过目环节兜住。
- **golden set 对比口径**：分布距离选型（逐指标 z-score 汇总 vs KL），阶段二定。
- **限速未知**：阶段二压测定；429 退避与降级链路要预案。
- **长线一致性天花板**：指纹守风格、审校守连贯，但百章级叙事质量仍依赖卷纲/复盘循环的质量——工具给了下限，上限在调参的人。
- **同质化**：多用户共用同一题材预设会产出同质小说。缓解：预设按层拆开取用（指纹带/黑名单/节拍模板独立组合）+ 各书独立大纲与卷纲驱动；预设本身不提供情节。
