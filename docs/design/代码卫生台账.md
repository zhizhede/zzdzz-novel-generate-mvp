## 九、Result 统一响应细化批（2026-09-21，未提交）

- **ok() → success() 全量改名**：7 个 controller 共 82 处调用点（Edit 逐文件 replace_all，未用 sed）
- **fail 泛型化**（修法一）：`static <T> Result<T> fail(...)`——失败值可出现在任意 `Result<T>` 返回位置（旧 `Result<Void>` 签名在带类型 controller 方法里编译不过）
- **独立 detail 字段**（第四组件）：通道分工写死在类契约——data 只装成功业务结果、detail 只装失败结构化明细；组件级 `@JsonInclude(NON_NULL)` 保成功响应 JSON 与旧形状逐字节一致（单测锁定 3 字段）；`BizException` 加 detail 双构造器、`GlobalExceptionHandler.handleBiz` 透传
- **双泛型 `Result<T,E>` 明示不做**：泛型是编译期语义，过 HTTP JSON 边界只剩 schema；fail 只在异常处理器一处产出，E 的编译期检查对不齐前端消费方
- 验证：新增 ResultTest 5 用例（success 形状×2/fail 带 detail/fail 无 detail/泛型 fail 编译位），全量 **49/49** 过
- 待续：detail 暂无生产者——第一批候选：状态冲突类失败带实际状态（A0006）、场景编辑带未过门禁条目；前端 api.js 尚未接 code/detail（期2/期3）
