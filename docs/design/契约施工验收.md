## 三A、② 批 v2 说明（已实施：硬中断落地）
硬中断 v2 已实施并实测：停止 = 落库 `cancel_requested` + 对 worker 线程 `Thread.interrupt()`（JDK HttpClient 同步 send 响应中断，在飞 LLM 调用毫秒级被弃，token 已花、结果丢弃）。实测：任务 24 场景 1 生成中途点停，**1.8 秒**后任务 INTERRUPTED（v1 为场景边界等待，分钟级滞后）。步骤行、章节状态、事件流水三处如实记「用户终止（硬中断）」。

## 三B、④⑤⑦ 实测实录（最有说服力的验收）

重启恢复真实演练：任务 22（ch61）两次被重启打断 → V20 恢复逻辑重新排队 → 新分道调度器认领 → 步骤状态行显式恢复（场景 PASSED 复用，12 行记录两次尝试）→ 期间 failureBrief 直接暴露一个**存量生产缺陷**（ch62 digest 时代遗留的 F72 编码使 ch61 的 digest 每次撞唯一键卡死）→ `proposeThreads` 幂等修复 → ch61 续跑至 **DIGESTED、任务 DONE**。观察/诊断/修复全程靠本批交付的状态行+failureBrief 完成——契约②④的价值即此。

## 四、用户验收步骤建议（10 分钟）

1. 登录 → 工作台：应见「待审批 1 章」徽标（ch61《活结》）；
2. 点徽标/去章节页 → 打开第 61 章抽屉：应有 [通过审批] 与 [打回…] 两键、无横幅（历史章无步骤行）；
3. 点 [打回…]：输入意见（≤200 字有字数限制）→ 确认 → 状态变 NEW、意见横幅出现、工作台多一条 RUNNING 任务——**这会真实重写 ch61，介意则先用第 62 章（DIGESTED，会被守卫拒绝，正好验证守卫）**；
4. 重生成完成后再开抽屉：[步骤] tab 应有 OUTLINE/SCENE… 状态行，意见横幅消失（已消费）；
5. 启动一个多章任务：队列 [当前阶段] 列应实时显示「章纲生成中→场景 N（检索/生成）→拼章+章级门禁→…」，[本章tokens] 数字滚动；点 [停止]：**约 2 秒内**任务变 INTERRUPTED，章节状态 INTERRUPTED、抽屉横幅显示中断位置，[断点续跑] 可从断点继续；多个任务在跑时可用 [全部停止] 一键急停；
6. manual 模式的书跑新章：章纲完成即停，抽屉出现 [批准章纲][打回章纲…]；
7. DIGESTED 章抽屉点 [编辑正文]：改一句保存 → 状态回 PENDING_APPROVAL、横幅提示 digest 作废 → 重新过审即重算事实账；
8. 生成前状态章（OUTLINED/FAILED/INTERRUPTED）场景条目点 [编辑]：保存即重过该场景机械门禁。
