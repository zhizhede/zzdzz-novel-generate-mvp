# 自动化小说生成系统 · 架构设计

> **2026-09-10 决策快照**：本平台定位为多用户多作品生成平台；审批默认 auto、MVP 合规后置、JDK21/无 Spring AI 先行等最新定案见 `docs/design/MVP共识与决策记录.md`，**与本文冲突处以该文件为准**。

> 目标：续写《人类、法师、地下城》，约束三个不变量——**人设不跑偏、节奏不跑偏、写手风格不跑偏**。
> 形态：工作流为主干，AI 介入部分节点，agent 只用在收益明确的位置。
> 依据材料：`docs/style/写手风格蒸馏.md`（风格指纹，不入库）、`docs/novels/手搓/`（正典语料，不入库）、`docs/novels/现成文章/咱家是猫，在观察人类-纯ai/`（纯 AI 对照组，不入库）。

## 一、先回答"为什么会跑偏"（对照组证据）

对 24 章纯 AI 样本的实测：

| 漂移类型 | 对照组实测证据 | 根因 |
|---|---|---|
| 节奏漂移 | 章长 2,502–8,512 汉字，3.4 倍波动；中段注水（第 7/9/13 章 8K+），结尾赶工（第 19/22/24 章 ≈3K） | 字数预算不在模型手里的确定性层面，靠模型自觉 |
| 腔调漂移（AI 通用腔回填） | 公式化句式高频复现："不是A——是B"式对仗、"混乱程度：中等偏高"式系统化吐槽、诗化收尾模板（"是像雪一样，一片一片，慢慢堆积"） | 无负面清单，模型向自己的高概率输出退化 |
| 结构单调 | 每章同一模板：感官开场 → 家庭切片 → 来客/事件 → 猫生哲学收束 | 无章纲层面的节奏设计，模型复用上一章结构 |
| 事实/人设（此样本侥幸守住） | 叙事者单一+口头禅复沓（"咱家是猫。还没名没姓。"）起到锚定作用 | 说明**锚点有效**——但这不能靠运气，要靠机制 |

结论：**跑偏不是 prompt 写得不够好，而是不变量被交给了模型。** 架构的核心原则只有一条：

> **凡是"不能变"的东西（设定、人设、风格硬规则、字数、时间线），全部外置为数据和代码；模型只做有界填空；每章过门禁；通过后写回状态层。**

## 二、总体架构（五层）

```
┌─────────────────────────────────────────────────────────┐
│  资产层 canon/（人写+人批，AI 只提案）                      │
│  人设卡 · 世界规则 · 时间线 · 伏笔账本 · 风格包(蒸馏报告)     │
└───────────────┬─────────────────────────────────────────┘
                ↓ 约束
┌─────────────────────────────────────────────────────────┐
│  规划层 outline/                                          │
│  卷纲(人写) → 章纲生成[AI] → 人批 → 章纲.yaml(场景级预算)    │
└───────────────┬─────────────────────────────────────────┘
                ↓ 规格
┌─────────────────────────────────────────────────────────┐
│  生成层 generate/                                          │
│  上下文打包[代码] → 场景草稿[AI,逐场景] → 拼章[代码]         │
└───────────────┬─────────────────────────────────────────┘
                ↓ 草稿
┌─────────────────────────────────────────────────────────┐
│  门禁层 gate/（防跑偏的主战场）                              │
│  机械校验[代码] → AI评审[结构化rubric] → 修订agent[AI,≤N次]  │
│         → 不过 → 人介入                                    │
└───────────────┬─────────────────────────────────────────┘
                ↓ 定稿
┌─────────────────────────────────────────────────────────┐
│  状态层 state/（记忆，防长程漂移的关键）                      │
│  章摘要digest · 角色当前状态 · 伏笔/承诺账本 · 黑名单自动更新  │
└─────────────────────────────────────────────────────────┘
```

人工介入点固定三处：**章纲审批、终审、canon 冲突裁决**。其余全自动。

## 三、节点清单：哪些用代码、哪些用 AI、哪些用 agent

| # | 节点 | 类型 | 说明 |
|---|---|---|---|
| 1 | 章纲生成 | AI | 输入卷纲+前情摘要+节奏模板，输出结构化章纲（YAML），人批后生效 |
| 2 | 上下文打包 | **代码** | 按章纲确定性拼装提示包：见 §五。禁止让模型自己"回忆" |
| 3 | 场景草稿 | AI | 一次只写一个场景（不是一章），带场景级字数预算 |
| 4 | 拼章 | 代码 | 按场景顺序拼接、统一分隔符、统计基础指标 |
| 5 | 机械校验 | **代码** | 正则/统计级风格门禁：见 §六。毫秒级、零成本、不可贿赂 |
| 6 | AI 评审 | AI | 结构化 rubric 打分（人设/POV/时间线/风格四维），输出 JSON，含原文行号证据 |
| 7 | 修订循环 | **agent** | 收到门禁报告→定点改写→重跑门禁，上限 2–3 轮，仍不过则升级人工 |
| 8 | 章摘要 digest | AI | 定稿后把本章压缩为"事实账"（谁做了什么、状态变化、新伏笔、回收了哪个伏笔） |
| 9 | canon 更新提案 | AI | 从 digest 生成 canon diff 提案，**人确认后才合入** |
| 10 | 续写检索 | **agent**（可选） | 需要引用前文细节时，用工具查 canon/digest/全文索引，而不是塞全文进上下文 |

agent 只出现在 7 和 10：它们是"反馈驱动、有明确工具、有终止条件"的封闭循环。**反对**导演/作家/编辑多 agent 自由协作写作——调试困难且漂移责任无法定位，留作 v2 实验区。

## 四、数据模型（目录即数据库，MVP 不用外部存储）

```
novel/
  canon/                      # 资产层：唯一事实源
    characters/
      塞拉斯.yaml             # 见下方人设卡格式
      坎德尔.yaml
    world/深梯城.yaml          # 制度、地理、魔法规则
    timeline.yaml              # 已发生事件（按章）
    foreshadows.yaml           # 伏笔账本：id, 埋设章, 计划回收章, 状态
  style/                      # 私有风格资产，不进 git；规划迁入 PostgreSQL（见 §八）
    写手风格蒸馏.md             # 已有（docs/style/）
    exemplars.md               # 冻结的手搓范例段（few-shot 用，永不改写）
                               # 含未发布手稿原文，蒸馏报告以 E/V 编号引用
    refrains.txt               # 必须复现的指纹词：来着/好X/还有/顺便…
    banned-phrases.txt         # AI腔黑名单：自动+人工维护
  outline/
    volume-1.yaml              # 卷纲（人写，已有素材在第一章文件头部）
    ch-003.yaml                # 章纲（AI 生成，人批后冻结）
  state/
    digests/ch-001.md …        # 每章事实账
    character-state.yaml       # 角色当前状态（伤势/关系/知情范围）
    style-metrics.json         # 手搓基线指标 + 最近N章实绩（回归监控）
  text/
    ch-003.md                  # 定稿正文
  reports/
    ch-003-gate.json           # 门禁报告（机械+AI评审），审计用
```

关键 schema 示例——**章纲**（节奏不跑偏的执行单元）：

```yaml
chapter: 3
title: 灵魂检测
pov: 塞拉斯
budget: { min: 1800, max: 2400 }        # 汉字，硬预算，门禁强制
hook_type: 信息揭示                       # 与上一章不同类型，模板轮换
temperature_of_scene: 冷                  # 冷/热交替，防全篇一个温度
scenes:
  - id: 3-1
    location: 教会附近
    present: [塞拉斯, 坎德尔]
    goal: 观察灵魂检测全流程
    must_reveal: [检测仪式的三道工序]      # 信息植入清单，评审对照
    must_not: [塞拉斯施法]                # 禁止事项，评审对照
    words: 700
  - id: 3-2
    goal: 心理描写暗示塞拉斯是无印魔法师
    emotion: 表面平静/内心紧绷
    words: 500
```

**人设卡**（人设不跑偏的执行单元）：

```yaml
name: 塞拉斯
identity: 人类身份学者 / 实为魔法师
voice_samples:        # ← 从手搓原文逐字摘录，few-shot 锚，最重要
                      #    原文存 exemplars.md（不入库），人设卡以编号引用
  - V-SL-1
  - V-SL-2
  - V-SL-3
tics: [左手碰耳钉, 打哈欠, 黑眼圈, 敬语客气但像对物体说话]
forbidden: [热血宣言, 长篇说教, 主动暴露情感]
arc_note: 对地面世界的倦怠（第二章结尾耳钉落地），仅内心戏呈现
```

## 五、上下文打包（防"记忆漂移"的核心）

单场景生成的提示包，全部由代码拼装，总量控制在 6–8K token：

| 组成 | 来源 | 大小 |
|---|---|---|
| 风格硬规则（蒸馏报告§六 prompt 片段） | style/ | ~400 字 |
| 风格范例 2–3 段（**冻结原文**，非改写） | exemplars.md | ~800 字 |
| 出场角色人设卡（含 voice_samples） | canon/characters/ | 每人 ~300 字 |
| 角色当前状态 | state/character-state.yaml | 每人 ~100 字 |
| 前情：最近 2–3 章 digest + 相关伏笔 | state/digests/ | ~800 字 |
| **上一章末尾原文最后 10–15 行**（节奏衔接锚） | text/ | ~400 字 |
| 本章禁用词快照（近期高频词自动生成） | banned-phrases.txt | ~200 字 |
| 本场景规格（goal/must_reveal/字数） | 章纲 | ~200 字 |

**不放**：全书正文、完整世界观文档。前文细节靠 digest + 检索（节点 10），检索不到就触发"canon 缺口"上报，而不是让模型编。

## 六、门禁层细则

### 6.1 机械校验（代码，先跑）

从手搓基线（`style-metrics.json`）算指标区间，超出即 fail：

- 对话「」覆盖率 100%；文书《》格式合法
- 顿号每千字 ≤ 1（手搓基线接近 0）
- 行均字数、段落长度分布偏离基线 > 2σ
- 对话行句末标点比例、破折号密度区间
- 章长落在预算 ±15%
- banned-phrases 命中数 = 0（黑名单随章节滚动：连续 3 章高频出现的非指纹句式自动入候选，人确认）
- refrains.txt 指纹词出现次数 ≥ 下限（防风格被"洗白"）

这套检查能当场拦掉对照组样本里的大多数问题（超长章、AI 腔模板句）。

### 6.2 AI 评审（结构化，不许自由发挥）

四维 rubric，逐项输出 `pass/fail + 行号证据 + 一句话修改指令`：

1. **人设一致性**：对照出场角色的 forbidden/tics/voice_samples 逐条核对
2. **POV 纪律**：是否越权写了 POV 角色不知道的信息
3. **时间线与事实**：对照 timeline/digest 是否矛盾
4. **风格偏离**：与范例段对比，节奏/温度/幽默装置是否在

### 6.3 修订 agent

输入=草稿+门禁报告，动作=只改被点名的行，输出=diff。每轮改完**重跑全部门禁**（防止改 A 坏 B），2–3 轮不过 → 保留双方版本，升级人工。

## 七、续写冷启动（把现有两章接进系统）

1. `ingest`：导入第一、二章手搓正文 → AI 生成两章 digest + character-state 初稿 → **人校**
2. 人设卡从手搓原文摘 voice_samples（已有闪回素材可补充次要角色），人审
3. 卷纲已在手搓文件头部（场景 1–7 笔记）→ 结构化成 `volume-1.yaml`，人确认
4. 生成 ch-003 章纲 → 人批 → 进入主流程

## 八、模型、存储与工程配置

- MVP 全节点用 `ai-config.md` 里的 MiniMax-M3，靠 prompt 分角色；门禁评审节点后续换异构模型（不同厂商）以去除"自己评自己"的相关性
- **生成温度分层**：草稿 0.8–1.0（要味道），章纲/digest 0.3（要稳），评审 0（要一致）
- `ai-config.md` 里的 api_key 已 gitignore（从未提交过 git），但文件曾以明文存在，建议尽快轮换该 key
- 所有中间产物（章纲、digest、门禁报告）落盘为文件，可重放、可 diff、可回滚——这是排"漂移"的唯一手段

### 8.1 存储演进：风格资产入库（PostgreSQL 16）

风格资产与 canon 是私有 IP，**不进 git**，规划以 **PostgreSQL 16** 为唯一真相源。MVP 早期仍用本地文件（`docs/style/`、`novel/`）冷启动，跑通"文件 → 库"一次性导入脚本后切换：

| 内容 | 存法 | 消费方 |
|---|---|---|
| 硬规则阈值、banned-phrases、refrains | 结构化规则表（键值/阈值行） | 机械门禁直接读表执行 |
| 风格范例段（E01–E10）、语气样本（V-*） | 文本行 + **MiniMax embedding**（pgvector 扩展） | 上下文打包节点按场景语义检索召回，不整段塞 prompt |
| 人设卡、世界规则、时间线、伏笔账本 | 结构化表（JSONB） | 上下文打包 + AI 评审 |
| 章纲、digest、门禁报告 | 版本化表（按章+轮次） | 重放与回滚 |

设计约束：**embedding 只用于"检索哪段范例"，不用于"判断是否合规"**——硬规则门禁必须是确定性的表驱动检查，语义相似度不能当门禁判据（阈值漂移不可解释）。

## 九、MVP 里程碑

| 阶段 | 交付 | 验收标准 |
|---|---|---|
| M1 单章直通 | 章纲→打包→生成→拼章→机械门禁 | ch-003 全自动产出，机械门禁通过 |
| M2 评审闭环 | AI 评审+修订 agent | 首过率>50%，3 轮内通过率>90% |
| M3 记忆续写 | digest 状态层+冷启动 | 连续生成 3 章无明显事实矛盾 |
| M4 风格回归 | style-metrics 监控+黑名单自动更新 | 连续 5 章风格指标不漂移 |
| v2 实验 | 检索 agent、异构评审、多agent | 对比 M4 基线 |

**验收的硬指标**：把手搓两章当 golden set，每章生成跑 10 次，统计门禁首过率与风格距离（§6.1 指标向量与基线的偏差）；另把对照组《咱家是猫》喂给同一套门禁做负样本测试——它应当在章长与 AI 腔两项上挂掉，以此证明门禁真的在拦东西。

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| digest 本身失真 → 错误滚雪球 | digest 人审（MVP 阶段每章都审）；伏笔回收时强制对照原文检索 |
| 门禁过严 → 文字变"合规但难看" | 机械门禁只管"指纹不丢"，"好不好看"只进人审，不设 AI 主观门槛 |
| 章纲预算与故事需要冲突 | 预算修订走"改章纲"而非"放任超长"，修订留痕 |
| 单模型长期自 mined 黑名单过拟合 | 黑名单只拦句式不拦内容；每 5 章人检一次 |
| 6 千字语料 → 指标基线置信度低 | 指标区间设宽容初值，随定稿章数滚动收紧 |
