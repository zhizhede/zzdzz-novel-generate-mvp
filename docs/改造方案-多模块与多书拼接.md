## 阶段一：多模块化基建

### 1.1 目标形态（6 模块，Maven parent）

```
zzdzz-novel-generate-mvp (parent pom, 依赖收敛+enforcer)
├── novelgen-common     # ErrorCode/BizException/Result/工具（9 类，近叶子）
├── novelgen-model      # entity33 + vo45 + dto8 + enums10（零反向依赖）
├── novelgen-data       # （实施修正，原方案写 novelgen-dao）Mapper 32 + XML 27 + Flyway SQL
│                       #   + service/data 接口与实现 64 类——两层合并，行 record 免搬家；依赖 model
├── novelgen-llm        # LlmPort/LlmJson/LlmNode/MiniMaxClient/PromptCatalog 12 类
│                       #   + PromptTemplateService（实施修正：物理下沉于此，破 llm→service 环）；依赖 data/common
├── novelgen-service    # 101 类大包（唯一泥球，不再细分）；依赖以上全部
└── novelgen-app        # 启动类/controller10/runner/config/web三件套 + application*.yaml；依赖 service
```

依赖方向（编译期强制，单向无环）：
`app → service → {llm, data} → {model, common}`，且 `llm → data`（实施修正：Resolver/MiniMaxClient 调 service.data 行为接口，合并后由 data 承接，方案原图的兄弟关系不成立）

### 1.2 拆分要先清的 3 处逆向边（摸底实锤）

| 逆向边 | 现状 | 修法（实施修正：①②合并执行） |
|---|---|---|
| dao→service | 8 个 Mapper 引 `service.data.*` 的 row record | ~~row record 搬到 model/query~~ → **实施改法**：`service/data` 整包与 `dao` 合并进 `novelgen-data` 模块，层内自洽、零 import 改动（摸底发现 data 层零反向引用，搬 record 是多余动作） |
| llm→service | `MiniMaxClient:11-12`、`LlmProviderResolver:4` 引 service.data 行为接口 | 同上并入 data；另 `LlmJson`/`PromptCatalog` 对 `PromptTemplateService` 的依赖 → 该类物理下沉 llm（第 4 处定点修） |
| model→service | `FingerprintMetricVO:4` 引 `GateService`（唯一 1 处） | 指标中文名下沉 `model/vo/MetricLabels`，GateService 改静态导入（按方案执行 ✓） |

service 根包 37 类同包互引（ChapterPipelineService 牵 13 个同侪）**不拆**——这是业务复杂度不是模块边界问题，阶段一不碰。

### 1.3 执行顺序（每步 `mvn clean test` 全绿才进下一步）

1. parent pom 建骨架 + enforcer（Java 21 / Maven 3.6+ 已配；编码 UTF-8 + 依赖收敛为实施时补齐）→ 空模块逐个挂上
2. `common`（连带把 `LlmException` 归位或 handler 留 app）
3. `model`（先修 FingerprintMetricVO 越界）
4. ~~row record 搬家~~（实施修正：改为 dao+service.data 合并进 data，见 1.2，此步消失）
5. `data`（Mapper + service.data + XML + Flyway）
6. `llm`（含 PromptTemplateService 下沉）
7. `service`、`app` 收尾，资源文件随 app（yaml）/ data（migration SQL）归位
8. 前端 web/ 不动，仍独立 `npm run dev`

**执行结果：8 步全部走完，每步 `mvn clean test` 全绿。**

预计纯移动 + 少量 import 修复，**不写任何业务逻辑**。风险点：MyBatis XML 的 namespace/别名扫描路径、`@MapperScan`、Flyway location 配置——都是配置行，逐个改。

### 1.4 基建与 hook（现状全无：pom 只有 spring-boot 插件，.git/hooks 只有 sample）

**最小集，不做全套工程化**：

1. **enforcer 插件**（随 parent）：`requireJavaVersion 21` + `requireMavenVersion 3.6+` + **编码 UTF-8 校验 + `dependencyConvergence`（实施时补齐，validate 实弹通过）**——多模块没它等于白拆。
2. **git 钩子（实施修正：装三道，不止 pre-commit；安装方式改拷贝进 `.git/hooks/`，不动 git config）**：
   - `pre-commit`：敏感文件闸（`*local.yaml` 在暂存区即拒，不信 gitignore——密钥入库实弹后的增补）→ 规约混提闸（code-standards 正文 + ≥10 Java 同提交即拒）→ `mvn -q compile`；
   - `pre-push`：禁直推 main（FORCE_MAIN=1 逃生）→ `mvn test` 全绿才许推；
   - `commit-msg`：type 白名单 + 冒号后 `\p{Han}` 中文开头 + ≤70 字符（§5.1 原脚本 locale 与字节区间双 bug，已修正）。
3. **规约更新**：`docs/code-standards.md` 加一节「模块边界」——依赖方向表 + 三条禁令：①service 不得引 controller/app ②model/common 不得引任何业务层 ③新类放哪个模块的判定表。AGENTS.md 同步铁律一行。
4. **不做**：checkstyle/spotless（全库重排 diff 污染历史，规约靠 review + 文档）、ArchUnit（模块边界本身就是编译期架构测试）、CI（本机单人开发，无远端 runner）。

## 阶段二：多书剧情摘取 + 全自动拼接（新模式 `SPLICE`）

### 2.1 模式定位

- `derive_config.mode` 新增 **`SPLICE`**；**MIGRATE 下线**（4 类 14 处主代码 + 向导前端，耦合面已摸清）。
- RESKIN 暂留（本轮不动，验证书还在）。
- 拼接**无人工确认**（用户定调），兜底靠结构校验 + 一轮拼接审校（仍自动、BLOCKER 重写 ≤2）。

### 2.2 全链路（四步，新任务 `TaskKind.SPLICE`，建书事务提交后入队）

```
①摘取   N≥2 个已解析样本 → 跨书聚合素材池
        （sample_plot_nodes 章级 summary+beats；现读取全是单样本 listBySample，
         新增跨书聚合 DAO 查询即可，样本解析链复用不动）
        ↓
②拼接   新 LLM 节点 derive_splice（无人工确认）
        输入：素材池 + 目标章数 + 读者设定（题材/主角名）
        输出（一次结构化 JSON）：
          a. 统一设定：新人物名表（防多书撞名）、统一时间线、世界规则 → 落 canon+素材卡
          b. 新全书大纲 → canon 大纲
          c. 拼接表：逐章指明「取自书X第Y章素材 + 缝合改编指示」
        自动落库：大纲 + 章行 goal/hook + beats 物化场景
        （复用 insertPlan/beatsToScenes/materializeScenes 整套现成写路径）
        ↓
③前情种子  为拼接章合成初始 world_state/facts/summary
        （从素材池各章 summary 生成「前情 digest」——否则首章起
         ContextPacker 吃「无前情」占位，跨源缝合处必断链）
        ↓
④生成   走既有管线：场景见章纲即跳过 → 生成 → 门禁 → 审校 → digest 滚动
        autoContinue 接续，目标章数一次预物化到顶（绕开续卷守卫）
```

### 2.3 生成期间「逻辑通顺」保障（全部复用，不新造防线）

| 防线 | 作用 | 状态 |
|---|---|---|
| 场景蓝图 = 拼接表物化 | 每章方向被钉死，AI 不自由发挥 | 复用（outlineStep 见场景即跳过） |
| 审校 continuity 四问 + 时序 | 缝合处断裂、前后矛盾 | 复用（V42 时间锚已落） |
| character_states 账 + audit | 多书人物归一后的人名/位置一致 | 复用（②的统一名表喂入） |
| 世界状态/伏笔账/事实账 digest 滚动 | 跨章连贯 | 复用（③解决冷启动） |
| replan 禁令（migrate 同款） | 防自愈把拼接素材重写掉 | 改判据：`migrate()→splice()` 并存 |
| 卷规划守卫（同款） | 防「AI 规划一卷」销毁预物化章 | `assertMigratedNotOverwritten` 加 SPLICE 分支 |
| 拼接审校（新增，1 轮） | 全自动下防拼歪：拼接表出库前查结构+跨源冲突 | **新增**，BLOCKER 重写 ≤2 仍自动 |

### 2.4 前端（向导 WizardView）

- 开书模式三选一：原创衍生 / **多书拼接**（替换「剧情迁移」入口）/ 换皮；
- 拼接模式：多选样本（≥2）、目标章数、主角名；完成页直接去工作台生成（同迁移）。

### 2.5 验收口径

探针：2–3 个样本各摘数章 → 拼一本 10 章探针书全自动跑完 → 四档统计（一次过/轮内修/重写后过/带标记放行）+ 缝合处专项人工通读（跨源边界章）。`mvn test` 全绿 + 新增：模式归一化、跨书聚合、拼接表结构校验、守卫 SPLICE 分支各一组。
