# 设计 vs 实现 对照审计（2026-09-15）

> 方法：`docs/design/` 三份文档逐条 vs 当前代码（main + 未合分支），证据给到文件级；未核实项标「待核」不下结论。
> 两类偏离分开记：**欠账**（设计明确要求，实现没有）与**演化**（实现走了文档没写的路，多经用户确认，如卷纲自动规划、评审五问、RAG 提前）。
> 本审计只记事实与欠账，修复顺序由用户定。

## 一、最重的发现：设计里的「人」有六处，实现只剩一处

设计文档明确要求的人工介入点：

| 设计出处 | 介入点 | 实现状态 |
|---|---|---|
| 架构§二:54 | 章纲审批 | ✗ `OUTLINE_APPROVED`/`DRAFTING` 全代码库零引用（V1 CHECK 里的化石） |
| 架构§二:54 | 终审 | △ 存在；曾每次 500 一个月无人发现；无打回/意见（→流 A） |
| 架构§二:54 | canon 冲突裁决 | ✗ 无对应物（素材卡只有一句提示词"不得发明矛盾设定"） |
| 架构§三 节点9 | canon 更新提案→人确认合入 | ✗ digest 不提卡（backlog「digest 提卡」）；伏笔 proposed 采纳无 UI |
| 架构§十 风险表 | digest 人审（MVP 每章都审） | ✗ auto 模式 digest 即终态，无确认流 |
| 架构§6.1 | 黑名单滚动候选→人确认 | 待核（未见实现） |
| 共识·首个切片 | 章纲人可编辑后视为批准 | △ 卷纲行可编辑；场景级章纲只读 |

结论：**「默认 auto 自动过审」被实现成了「auto 排除人」**。设计的产品形态是"混合审批"（人工通道常设，auto 是默认策略），实现把"默认"读成了"只此一种"——manual 通道曾每次 500 一个月无人发现，即为通道名存实亡的实证。

## 四、欠账清单（按对手感的影响排序）

1. **章纲审批卡点**（含打回）——设计三处之首，人工介入最便宜的位置（章纲重写=几十秒 vs 终稿重写=35 分钟）
2. **digest 人审/解耦**——事后否决权的地基，backlog 既有项
3. **canon 冲突裁决 + digest 提卡**——节点 9 整体缺失
4. **保留双方版本**——修订对比与回滚
5. **黑名单滚动候选+确认、style-metrics 回归监控**——M4 验收欠账
6. **golden set 首过率统计 + 对照组负样本测试**——验收手段缺失：门禁"是否真的在拦东西"目前无数据
