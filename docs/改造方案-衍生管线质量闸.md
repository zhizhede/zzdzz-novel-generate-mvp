# 改造方案：衍生管线质量闸（结局闭合 · 元素回收 · 清稿 · 立项评审）

> 状态：**方案（未实施）**。方案层文档（宪法 §三.④），落地时以本方案为准拆任务单；与《最高约束.md》/AGENTS.md 冲突时以上位为准。
> 日期：2026-10-17。证据基线：线上 derive_gen 书 33（run 15）与书 50（run 16）实弹审稿 + 源码/库表对证。

## 一、背景：两本书、同一份旧合同

两份外部审稿与库内证据对表后，确认问题不是「模型写不好」，而是**衍生管线在合同层（配置/规划/质检）给不出闭合与回收的义务**：

| 证据 | 书 33《月潮盐崖塔》(run 15) | 书 50《重蹈覆辙的人们》(run 16) |
|---|---|---|
| `run.param_outcome` | **开放** | **开放** |
| 标签 | 推理+奇幻 | 冒险+复仇+奇幻+悬疑+言情（5 个） |
| 真相卡 | 有（悬疑/推理体裁⑥b必出） | 有 |
| 审稿结论 | 69/66 分：核心诡计未闭合、结尾模板复读、正文残留挂拍标记 | 43 分：诡计双轨、体量超载、动机横跳、结局再未闭合 |
| QC 状态 | qc_round=1 **REWORK**（logic/voice/domain 全 false）——书仍被导出投稿 | 仍在 DRAFTING（56 章规划、18 章成稿、125 拍、QC 未跑） |
| 其它 | content 里 ch7–44 残留 LLM 吐的章注回声（ch18 甚至保留 `本章X字` 占位符）；`anti_repro=关` | `story_settings` 为空；`anti_repro` 同样未开 |

病灶同源，可归纳为三层：

1. **配置层**：`outcome`（seed 随机抽，`DeriveSampleService`）与真相卡（⑥b 推理体裁必出）互不相认——「末章可留悬念」和「结局章须还原三要素」两个合同打架。
2. **数据层**：拍体系只有 `铺垫/情绪/事件/反转/抉择/收束`，「拍兑现」只核出现一次；**没有线索/道具/威胁/承诺的回收账**。非推理体裁 truth 直接省略，等于零账本。
3. **流程层**：⑧ 已抓到 logic 硬伤并判 REWORK，但**导出/投稿不看 `run.status`**；且无「大纲出口评审」——烂合同一路写到底才发现。

另有两个附属 bug/缺口：

- **清稿缺口**：三个写稿提示词（`WRITE_PROMPT_INDEPENDENT/CONTINUOUS/REPAIR_PROMPT`）仍要求 LLM「正文最后单独一行输出章注」，与 `DeriveWriteService` 类注释宣称的「章注不再由 LLM 输出（P0）」矛盾；`COMMENT_PATTERN`（`本章(\d+)字…挂拍[\d,，\s]*`）匹配不上 LLM 实际吐出的 `seq` 前缀/`X字` 占位符变体，剥离失败残留进正文。QC `FLOW_PATTERN` 不含章注字样，「流程痕迹=0」放行。
- **复读放大器**：连续会话前情注入带「前章正文尾段」，模型反复看见自己上一章的结尾句式；⑧ 五项快检没有任何一项管章末意象多样性。

## 二、目标与非目标

**目标**

- 推理/悬疑+真相卡的书**结构上不可能**再出「未完结」（33/50 型病灶的机器级根治）。
- 全题材具备**元素回收账**：埋了要出现、出现了要收口，未回收可机器计量、可拦截导出。
- 正文**零管线痕迹**：章注只存在于 `chapters.comment` 列，content 永不含 `<!--` 回声。
- REWORK 状态的书**无法进入导出/投稿通道**。
- 大纲在开写前经过一次**立项评审**（规则单轨/体量预算/动机链/闭合），烂合同死在 ⑥b 出口。
- 章末意象复读显著下降（回到书 33 ch1–6 的水平）。

**非目标**

- 不追求「创意/融梗」的机器终审——立项闸只给风险信号（配合 `anti_repro`），像不像名作仍由人裁。
- 不改主站 zzdzz 管线（其伏笔账本已存在；本方案只动随机衍生链 derive）。
- 不引入新的整章重写触发路径——清稿类问题一律确定性处理（正则/提示词），**永不因章注残留触发过闸重写**（该路径曾因太慢被主动放开，不得回退）。

## 三、工作流插入点总览

```text
⑤采样 ──► ⑥a计划 ──► ⑥b填实 ──► ⑦逐章写正文 ──► ⑧QC ──► PASSED ──► 导出/投稿
              │           │            │              │                    │
              │        [P6 立项闸]   [P3 建账+挂账]   [P3 清算]            │
              │        [P2 outcome   [P4 前情瘦身    [P2 ⑧闭合硬判]       │
              │         裁决在⑤抽签]  + 结尾禁复读]   [P5 REWORK 禁导出]◄──┘
              │           │            │              │
              └───────────┴──── REWORK 回炉（现成链，≤2 轮）◄────────┘
```

- **P2 裁决规则**：改在 ⑤ 抽签处（最早、零 LLM 成本）+ ⑧ 判据兜底。
- **P3 元素回收账**：建账 ⑥b→⑦ 之间；挂账更新随 ⑦ 章完稿；清算在 ⑧ 内。
- **P4 结尾复读抑制**：⑦ 提示词/前情组装处；⑧ 轻量查重。
- **P5 导出闸**：导出入口判 `run.status`。
- **P6 立项闸**：⑥b 产出之后、⑦ 第一章之前，新增一次 LLM 评审步。
- **P1 清稿**：⑦ persist 路径（源头删指令 + 兜底剥离），不设质检硬拦。

## 四、分项设计

### P1 清稿闸（P0 bug 修，确定性，永不触发重写）

**问题**：提示词仍令 LLM 输出章注；剥离正则吞不下 `seq` 前缀与占位符变体；QC 不查 content 章注残留。

**改法**

1. **源头断供**：删除 `DeriveWriteService` 三个提示词中的「正文最后单独一行输出章注」条目（`WRITE_PROMPT_INDEPENDENT` 第 11 条、`WRITE_PROMPT_CONTINUOUS` 第 12 条、`REPAIR_PROMPT` 第 4 条后半）。
2. **persist 兜底剥离**：落库前从 content 剥离章注行，正则兼容：
   - 标准机器格式：`<!-- 本章\d+字，挂拍：[\d,，\s]* -->`
   - LLM 回声变体：`挂拍[:：]\s*(?:seq\s*)?[\d,，\s]*`、`本章[XxＸ]字`
   剥离只做文本清理，机器章注照旧写入 `chapters.comment`（P0 现行为不变）。
3. **QC 侧降报告不拦**：脚本项沿用「降报告不判负」口径（同 `BLACKLIST=降报告`），记录「剥离 N 章残留」；**不判 REWORK、不触发重写**。人工手动改通道保留。

**验收**：构造含三种变体的样本文本，剥离后 content 无 `<!--`；存量书 33 ch7–44 一次性回清脚本可重复执行幂等。

**涉及文件**：`DeriveWriteService.java`（提示词 + persist 路径）、`DeriveQcService.java`（脚本降报告项）、可选一次性回清脚本（`var/` 下，不入库）。

### P2 结局形状裁决（推理/悬疑 + 真相卡 ⇒ 强制闭合）

**问题**：`outcome` 与真相卡互不知情；`DerivePlanService` PLAN_PROMPT 规则 4 在 outcome=开放时合法授权末章留白；⑧ logic④ 对「结局未还原」只记 issue。

**改法**

1. **⑤ 抽签裁决**（`DeriveSampleService` outcome 确定处，约 188–192 行）：
   - tags 含 `推理` 或 `悬疑` 时，抽中「开放」改判「闭合」（或仅在 {循环, 闭合} 内抽）；
   - 多标签冲突（如 50 号的奇幻+悬疑）：**真相卡优先级最高**——只要产出 truth，结局形状即为闭合。
2. **⑧ 判据硬化**（`QC_PROMPT` logic 项④）：真相卡存在且 `reveal_chapter` 落在末章区间时，「真凶/动机/手法三要素未在结局章明确还原」直接 `pass=false`（现状已 fail-open 进 REWORK，主要是把判据从描述改为卡对卡硬条件）。
3. **文档同步**：`随机衍生工作流/` 对应文档升版号后补裁决规则（**先复制升版再改副本**，禁原地改）。

**验收**：单测钉住——tags=推理×outcome 抽中开放 ⇒ 落库 outcome=闭合；重跑 50 号同 seed 配置（新 run）末章章纲含收束语义。

**涉及文件**：`DeriveSampleService.java`、`DeriveQcService.java`、workflow 文档（升版副本）。

### P3 元素回收账（全题材，核心增量）

**问题**：非推理书零回收账；推理书真相卡只管线索；拍兑现不核呼应。

**新表**（`migration-derive/` 新迁移，版本号顺延）：

```sql
CREATE TABLE element_ledger (
    id            BIGSERIAL PRIMARY KEY,
    run_id        BIGINT NOT NULL REFERENCES run (id),
    seq           INT    NOT NULL,
    kind          VARCHAR(16) NOT NULL,
    name          VARCHAR(256) NOT NULL,
    summary       TEXT,
    plant_chapter INT,
    settle_chapter INT,
    status        VARCHAR(16) NOT NULL DEFAULT 'PLANNED'
                  CONSTRAINT ck_element_status CHECK
                    (status IN ('PLANNED','PLANTED','SETTLED','DROPPED')),
    created_time  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_time  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_element_run_seq UNIQUE (run_id, seq)
);
```

列注释：`seq` 账内序号；`kind` 取值 CLUE/PROP/THREAT/PROMISE/RELATION/FATE；`name` 元素名（人类可读）；`summary` 一句话语义；`plant_chapter` 埋设章（计划）；`settle_chapter` 回收章（计划，NULL=允许留白的氛围元素）。

**挂账（⑥b 末尾，P6 立项闸通过之后）**

- 真相卡 `clues`/`timeline_anchors` 原样入账（kind=CLUE/FATE）；
- brief + 章纲概览批量抽取一次 LLM（可并入 ⑥b 现有生成轮，不加独立往返）：道具、威胁、承诺、未解事件入账（kind=PROP/THREAT/PROMISE）；
- cast 人物关键状态变化入账（kind=RELATION/FATE）。

**挂账更新（⑦）**

- 每章上下文注入「未清算元素清单」（机制复用真相卡分段注入，`DeriveWriteService` 307–317 行同款）；
- 章完稿后在现有输出通道附带「本章碰过的元素 seq 列表」（写进章注解析旁路或独立小 JSON 字段；**不加独立 LLM 轮次**）——PLANTED/SETTLED 回填。

**清算（⑧）**

- 脚本层两条计数硬判：`PLANTED 后从未再出现`、`plant_chapter 已到仍未 SETTLED 且 settle_chapter 非 NULL`；超阈值（默认 3，可调）计入 verdict；
- LLM logic 扩展「按账对账」：埋设是否兑现、回收是否含糊；
- 题材分支判据（⑧ 按 tags 选择，同一套账不同清算规则）：
  - 推理/悬疑：线索必须在 `reveal_chapter` 收敛到 solution；
  - 言情：情感债（PROMISE 类）清零；
  - 通用：允许 ≤3 个 DROPPED（留白是艺术，欠账是事故）。

**回炉**：清算失败走现成 REWORK→⑥b 链；**禁止**为清账触发单章重写循环。

**验收**：单测覆盖脚本计数；构造「埋了不收」样本书验证 ⑧ 判 REWORK 且导出被 P5 拦截。

### P4 结尾复读抑制

**问题**：连续会话前情尾段自我模仿；⑧ 无多样性检查。

**改法**

1. **前情瘦身**：连续会话注入的「前章正文尾段」截取时**跳过章末最后一段**（保中段事实对齐，断复读素材源）。改动点：`DeriveWriteService` 前情组装处。
2. **写作指令加一条**：「章末收束意象不得与前情尾段同类，禁止复用纸角/影子/灯焰等既出现过的收尾意象」。
3. **⑧ 轻量查重（脚本）**：全书章末 2–3 句 ngram 重合率检测，超阈值点名章号；**初版降报告不判负**（质量问题≠结构失格）。

**验收**：同 seed 对照组（改前/改后各 1 本）章末相似度分布对比。

### P5 导出闸：REWORK/FAILED 禁导出

**问题**：书 33 在 `run.status=REWORK`、44 章全 DRAFTED 状态下被导出投稿，带着整张未清偿的 logic 硬伤账出门。

**改法**：导出/投稿入口（derive 侧导出 API 与任何面向投稿的下载通道）前置检查：

- `run.status != PASSED` ⇒ 拒绝导出，返回明确人话（「质检未通过（REWORK 第 N 轮），问题清单见 QC 报告」）；
- 本地人工导出（运营通道）保留但需显式参数 `force=true` 并审计留痕。

**验收**：REWORK 书导出返回业务错；PASSED 书正常；force 通道有日志。

### P6 立项闸（⑥b 出口的大纲评审；六判据，2026-10-17 随照夜行审稿扩充）

**问题**：50/51/照夜行三稿连续证明——体量超载、动机横跳、职能漂移、真相翻转、跨稿母题复读全部**诞生于大纲层**，开写前无人审（分数天花板 43→57→60 全卡在这里）。

**形态**：⑥b-0 全局头之后（或 ⑥b 全窗完成后、⑦ 开写之前）新增一次 LLM 立项评审（节点 `derive_gate`），输出 `{"verdict":"GO|REWORK|REJECT","issues":[…],"directive":"REWORK 时的减法指令"}`。落点头之后更优：头已含 cast/truth/brief，判据 1/3/4 可直接对产物判，且 REWORK 仍走整本回炉链。

**六判据（自然语言判据 → 提示词硬条件）**：

| # | 判据 | 规则要点 | 来源实证 |
|---|---|---|---|
| 1 | 规则单轨 | truth 存在 ⇒ 超自然只许做氛围、禁入手法层；诡计只能一套可理性化规则 | 50号双轨打架 |
| 2 | 体量预算 | 主线≤1；支线≤1（中篇）/≤2（长篇）；**人命≤4**；机关/死亡/揭穿类高密度事件中篇≤3、长篇≤5；beat 总数超字数带折算上限打回 | 50/51/照夜行三连（run19 实测 124 拍全事件向） |
| 3 | 动机链 | 主要人物每次立场变化须有 ≥1 个铺垫章；隔门式反复、堕落无台阶直接 REWORK | 50/51 横跳 |
| 4 | 闭合 | 与 P2 合流：truth 存在 ⇒ 结局章纲必须写明三要素兑现动作；先写死再留余韵 | 33/50/51 |
| 5 | 职能锁定 | 主视角/侦探的方法论与行为一致（「只记不断」者禁下场肉搏/潜入夺人质）；侦探与当事人职能不重叠 | 照夜行姜行舟职能漂移 |
| 6 | 母题查重 | 大纲产出与**母题黑名单**（`wordlist`，新增 grp='MOTIF'：抱遗骸疯唱、色相求饶、鞋印嫁祸、替身伏法、隔门加固……）+ 历史稿高频收尾母题比对，命中≥N 处点名要求换写 | 照夜行四稿连复读 |

**融梗信号**（判据 7，只报不拦）：与已知名作同构度偏高写入 issues 提示。

**回炉**：REWORK 带 `directive` 回 ⑥b 重生成（现成链，≤2 轮）；不过则 FAILED——书未开写即止损。**成本**：每 run +1 次 LLM 调用。

**伴随补丁（P6 落地时一起做，机制性根治母题复读）**：

1. **指纹登记前移**：`work_fingerprint` 现只在 ⑧ PASSED 登记——而 33 起无一过审，**越不过审越无防复刻数据**（死循环）。改为 ⑥a 抽中弧时即登记 BRIDGE 指纹（幂等），⑤ 同构弧阻断照旧只在 `anti_repro=开` 时生效；
2. **母题黑名单入池**：`wordlist` 新增 `kind=BLACKLIST, grp='MOTIF'`（零 DDL），⑥b 产出与 ⑧ 可 grep 词面 + P6 提示词注入语义比对；
3. **`anti_repro` 默认值**：建议衍生新书默认开——**默认值变更需用户明示拍板**，待批。

**验收**：用 run 19（照夜行）参数重放，预期 verdict=REWORK 且 directive 点名「人命超限/职能漂移/母题命中」；母题黑名单逐条 grep 命中数可复算。

### P7 字数档（已落码，2026-10-17；估档语义当晚用户二次定调）

`RunCreateDTO.wordsMin/Max` 可选：都传=显式带宽；半传报参数错；**都不传=AI 估档（`derive_word_band`，2026-10-17 深夜用户定调「留空初衷就是让 AI 自己判断字数与篇幅」，推翻早先「按 form 默认带」的短期档口径）**——LLM 按 tags/intent/style 判 form+带宽（用户已指定 form 则只估带宽），估出带宽**钳入 `FORM_WORDS` 档内**（LONG 10–20万 / SHORT_STANDALONE 1–3万 / LIGHT_NOVEL 8–16万 / LONG_INNER_SHORT 10–20万 / LN_INNER_SHORT 6–12万；AI 天然贪大，钳位护栏必留），失败 fail-open 回退「seed 抽 form + 形态默认带」。字数留空且 form 留空时**不再 seed 抽 form**（由 AI 一并判定）；字数已填时 form 缺省仍 seed 抽。落 `run.param_words*`/`param_form` 可复现（估档引入 LLM 后同 seed 跨次不保证同估档结果，显式带宽路径不受影响）。


## 五、落地顺序与里程碑

| 序 | 项 | 规模 | 依赖 | 里程碑 |
|---|---|---|---|---|
| 1 | P1 清稿 | 提示词 3 处 + 剥离正则 + 降报告项 | 无 | 存量 33 号回清；新书 content 零章注 |
| 2 | P5 导出闸 | 导出入口 1 处判断 | 无 | REWORK 书导出被拒 |
| 3 | P2 裁决规则 | ⑤ 约 10 行 + ⑧ 判据 | 无 | 推理/悬疑新 run outcome 恒闭合 |
| 4 | P4 复读抑制 | 前情截断 + 指令 + 查重函数 | 无 | 对照组相似度下降 |
| 5 | P6 立项闸 | 新服务/节点 + 回炉接线（六判据） | P2 | 50/51/照夜行参数重放被 REWORK |
| 6 | P6 伴随 | 指纹登记前移 + MOTIF 黑名单 wordlist + anti_repro 默认（待拍板） | P6 | 跨稿母题命中可点名 |
| 7 | P3 回收账 | 新迁移 + ⑥b/⑦/⑧ 接线 | P6（挂账在立项通过后） | 「埋了不收」样本书被清算拦截 |
| — | P7 字数短期档 | **已落码**（form 默认带宽，随下批部署） | 无 | 不传字数可建 run |

前四项（P1/P5/P2/P4）均为提示词/规则级改动，可先落；P6 次之；P3 是唯一动数据结构的，**实施前本方案过用户确认**。

## 六、风险与开放问题

1. **⑧ 单次调用输入膨胀**：回收账对账 + 立项评审都会加长 QC prompt——需控制账本条数（挂账时上限，如 40 条，超出合并），必要时拆两次快检。
2. **连续会话前情瘦身的副作用**：跳过章末段可能轻微削弱「章末钩子」的衔接——P4 落地后用对照组盯前 10 章钩子质量。
3. **多标签冲突的更多形态**：P2 只裁「真相卡 vs outcome」；奇幻+悬疑的「规则双轨」由 P6 规则单轨判据兜——若出现新的标签冲突形态（如言情+复仇的双主线），扩展到 P6 体量预算判据，不在 P2 里打补丁。
4. **run 16（书 50）仍在 DRAFTING**：新规则不追溯。是否停跑由运营决策；本方案建议停（写完只是多一份 43 分证据）。
5. **`anti_repro` 默认值**：本方案只建议打开，不擅自改默认——默认值变更需用户明示。

## 七、回归对照口径

实施后各用一个新 run 重放 33/50 的参数（同标签、同字数带）：

- 33 型（推理+奇幻）：outcome=闭合；结尾无案情悬空；content 无章注回声；⑧ PASS 或轻症。
- 50 型（5 标签长篇）：立项闸 REWORK 或 GO 后支线 ≤2、规则单轨、末章闭合。
- 通用：导出通道对 REWORK 书 100% 拒绝；元素账未回收数可查询。
