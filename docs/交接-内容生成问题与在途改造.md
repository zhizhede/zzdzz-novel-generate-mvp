## 2. 内容生成问题全景（核心）

### 2.1 转人工率升高 —— 在途修复中（本次交接主体）

**现象**：`PENDING_APPROVAL` 比例——源主角样本 26 章 0 转人工；换样本11后书 59=40%、61=50%、63 ch1 即转人工。

**四层根因（缺一会漏判）**：

| # | 根因 | 证据 |
|---|---|---|
| 1 | **审校预算只有 2 轮**：第 2 轮才新冒出的问题直接耗尽预算 → 转人工 | 书 63 ch1：r1 用印矛盾（修掉）→ r2 又出「称呼+时序」两个新 blocker → 无第 3 轮 |
| 2 | **结构性漏洞：修订轮只修 blocker**（`reviseForIssues` 里 `if (!blocker) continue`）——首轮 minor 不进修订清单，第 2 轮升级成 blocker 时已无预算。「minor 是免费升级成 blocker 的定时炸弹」 | 书 63 ch1 r1 的称呼/时序就是 minor，r2 变 blocker |
| 3 | **样本换了，不是系统变差**：源主角（哲思单线，几乎无记账型硬伤）→ 样本11（印/称呼/时序/物件多线交织） | 对账表见 STATUS |
| 4 | **审校变准了**：V42 场景时间线注入后，审校能对着时间账查时序（以前这类错**直接出厂**，书 59 ch2 时序颠倒就是漏网实锤）；查得全 → 第二轮更容易再揪出东西 | 书 63 ch2 r「钟点时序倒挂」即对着时间线查的 |

**关键澄清**：ch1 拦下的三处全是真硬伤（用印自相矛盾、称呼与大纲不符、时序倒挂），不拦就出厂——**问题不是「拦错了」，是「修的预算和手段不够」**。人称、密度两条新防线在 ch1 零误报（审校还明写「全章第一人称」）。

**修复设计（三档自愈梯子，auto 模式专用；manual 永远转人工）**：

```
审校闭环内（轮数内自修）:
  ai_review_rounds 默认 3（原2）；blocker 期间逐轮「修订→复审」
  修订清单 blocker+minor 一并修 + 输出前逐条自检（堵根因2）
        ↓ 3 轮仍 blocker
档1 保剧情重写（review_rewrite=1 默认开，全模式含迁移/换皮）
    清正文+场景草稿，章纲与场景蓝图保留 → 整章重跑（换皮/迁入剧情不毁）
        ↓ 仍 blocker
档2 换目标重写（review_blocker_replan / 无人续跑书；迁移换皮禁用——replan 会毁迁入剧情）
        ↓ 仍 blocker
档3 终态：review_auto_accept=1（默认）→ 带 `auto_accepted` 标记走既有 approve 出厂（事件流水可查、供离线抽检）；=0 → 转人工
        ↓ digest 失败
    回退转人工（不硬发没有事实账的章）
```

- 各档内 `attemptChapter` 同步重跑、结果直接返回，**不递归回 disposition，天然有界**。
- 与迁移/换皮契约不冲突：旧契约禁的是 `replan`（换目标会毁迁入剧情），档1 只清草稿正文、蓝图保留，是被允许的强自愈——这正是换皮书此前「只能转人工」的破局点。

### 2.2 机械门禁卡边 —— 已修（已 push）

**现象**：ch3 章长差 2 字两轮修不回、行均长 36↔15.65 两头翻、对话密度 30.44 vs 30.2 磨边界，每章白烧 2 轮章级修订 + 1 次断点重跑，本轮咬人 3 次。

**根因三连**：
1. `failedChecksText` 只打 baseline 不打 abs_max——密度失败显示「基线null」（模型不知道 30.2 上限，两次收敛到 30.44 卡死）；行均只显示中位数 23.68（模型朝它压，过冲到 15.65 跌破真实下限 20.13，真实带 [20.13,31.95] 从未被告知）；
2. 预设 68 是外部工具导入的 **9 指标子集指纹**，缺 `dialogue_density` 基线 → 密度上限恒为硬编码 30.2，与「信息密度红线推高对白」正面打架；
3. 章长+行均双指标互相拉扯且修订无方向指引 → 一轮修 A 坏 B。

**修复（已 push `caba482` + `67b6d76`，分支 `10/1007-门禁卡边反馈修复`）**：
- `failedChecksText` 按界别打全：双界→`（a~b）`、仅上限→`（上限b）`、仅基线→`（基线a）`；
- 修订模板加「指标修复方向」块（字数不足→补短行 / 行均超→拆长句 / 密度超→合并连续对白，多指标必须组合动作）；
- **密度主判据上移章级**（实测 12 个已成稿章章级密度 20.7–33.8 稳定；450 字场景单个「≈2.2/千字方差过大），场景级只留 1.5× 极端护栏（默认 45.3，只拦病理稿 55+）；
- 密度上限三级回退：书级 gate_config 键 **`dialogue_density_max`** → 指纹 abs_max → 30.2。

**实弹验证**：修订请求全部带上限、零「基线null」；场景级 cap=45.3 只拦 46+/55+ 病理稿，30.4–37 边界摩擦消失。

### 2.3 内容风控拒答 + 零中文稿 NPE —— 已修（已 push）

**现象链**（书 60 ch2 / 书 62 换皮）：输入含「失身/缠绵/床单殷红」→ MiniMax 内容审核整段拒答（60 字符英文 `The request was rejected because it was considered high risk`）→ `computeMetrics` 对零中文文本早退只给 `{"cjk":0}` 残缺 map → `checkScene` 拆箱 null **NPE 炸章**。

**修复**：
- **NPE（`a7d0bc8`）**：零中文/空文本返回与正常路径同键集的 13 个零值——消费方不炸；零值=最差稿 → 走「门禁不过带意见重写」自愈而不是崩。
- **输出侧红线（`f76b943`）**：15 个生成/修订模板统一「内容安全红线」——敏情节只用报告式中性概述干句、禁用高危词、只写结果不写过程；`ContentSafetyRedlineTest` 锁 15 模板字面+词表统一+arity 不变。
- **输入侧清洗（SQL 直改）**：**样本 11 的 plot_nodes（所有换皮/迁移书的输入源）**残留同批词——书 62 因此在换皮第 2 章被连拒 fail-fast；清洗 3 行节点（book/seq1/seq2）后书 63 换皮 33 章 **0 拒答**。
- **教训**：红线只管输出；样本节点、导入摘要这类**输入源要单独清洗**。

### 2.4 人称漂移 —— 已修（已 push `41a8e38`）

三层：读取链 `DeriveSupport.effectivePov`（章级→书级→null fail-open）→ 场景注入（derive_pov 禁止章内切换）+ 章纲落 `chapters.pov`（validateScenes 返回根节点防字段静默丢失）→ 机械 `pov_consistent`（剥对白只看叙述层）+ AI 审校第 5 查。
**实弹**：书 60 ch2 真漂移被「机械 value=0 报到 + 审校 blocker 判出 + 修订 0→10 修回」完整闭环；正常章 50 轮 0 误报。`pov_check_block` 默认 0 只报不拦（待观察开拦截）。

### 2.5 章内时序 —— V42 已落，端到端未实弹
