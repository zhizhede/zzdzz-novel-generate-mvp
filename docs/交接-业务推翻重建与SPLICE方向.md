## 0. 一页话

这是一个多用户 AI 小说自动生成平台（Java 21 / Spring Boot 3.5 / PostgreSQL+pgvector / Vue3）。**2026-10-08 用户定调：原核心卖点「剧情迁移」不做了**，业务整体转向——

> **新方向：多本书剧情摘取 + 全自动再拼接**。从 N 本样本各摘剧情素材，AI 自动设计拼接大纲（**无人工确认**），生成期间必须保证结果逻辑通顺。

实现分两阶段：**阶段一（基建）已完成并合入分支 `10/1008-多模块基建`**；**阶段二（SPLICE 业务链）已设计、零实现，且被用户明令封印——未经用户允许禁止开工**。

### 0.5 阶段二目的与取样层级（2026-10-08 用户定调，交接必读）

> 此前文档只有验收口径（§2）没有「为什么做」。以本节为准。

- **目的**：把小说从「作品」变成**可按指定逻辑取样拼接的组合空间**——素材元素化＝建空间，拼接＝按设定取样，tag＝取样约束，逻辑通顺＝可行域。产能模型从「素材数的线性变现」（1 本样本=1 本新书）变为「组合数」；量产、无人是这个空间的属性，不是目的本身。
- **取样层级（阶段二基线）**：拼接**至少两层取样**——一层**大框架**（书/卷骨架）、一层**小框架**（章/beat 节拍），全部素材做成**随时按指定逻辑取样、拼接、复用**的统一形态。两层可跨书取源；拼接表必须分层带来源（provenance）。
- **后续扩展必做（用户原话：「长篇还要在中间再加一层更细的取样迁移」）**：短篇两层基本成立；**长篇须在两层中间再加一层更细的取样迁移层**——列为基建/规范的后续扩展必做，层标记、provenance、取样器层参数按三层可扩预留，不许写死两层（规范落点：`code-standards.md §1.2`）。

## 1. 推翻了什么

旧模式 `derive_config.mode` 三值：

| 模式 | 业务 | 处置 |
|---|---|---|
| `ORIGINAL` 原创衍生 | 选样本→AI 大纲→防复刻三闸→生成 | **保留**（不是本次推翻对象） |
| `MIGRATE` 剧情迁移 | 样本逐章剧情+节拍原样灌入新书（用户此前称「最重要」） | **已下线（2026-10-08 M2/M3 完成，ADR-0001）**——后端判据/克隆/换名/向导入口全拆，历史 mode 值经 V43 归档 `preset=RESKIN` |
| `RESKIN` 换皮 | 保剧情骨架、外衣全随机重造 | **暂留**（库里有验证书在跑，用户没说动它） |

推翻的直接起因：用户认为逐本迁移做不大，要的是**跨多本书摘取素材、机器自动拼成新故事**的量产路线。注意口径变化：旧迁移要人工确认章节映射；新拼接**全自动、不设人工确认关卡**，靠「结构校验 + 一轮拼接审校（仍自动）」兜底。

## 2. 新业务的验收口径（用户原话整理）

1. 输入：**N≥2 本书**的已解析剧情素材（样本解析链已有，`sample_plot_nodes` 章级 summary+beats）；
2. 拼接：AI 一次产出「统一设定 + 新大纲 + 逐章拼接表（哪本书哪段接哪段）」，**不问人**；
3. 生成期质量底线：**逻辑通顺**——缝合处不能断链、人名时间线不能穿帮；
4. 量化目标沿用现有口径：全自动通过率（目标 99%），人工只做事后抽检。
